# Order: security review, INSTALLERS and DOWNLOADER, v5.0 Phase 4.5 plan 045-01 (read-only; report in your final message, no files)
Frame: the localhost API (server.py, token-gated, loopback only) hands these modules a NAME string and a literal `true`, never a path, URL, command or version. `engines.install` derives its own plan; `fetch.download` accepts only catalog rows; `fetch.evict` removes only ledger-recorded paths. Actors in scope: a web page, another process of the same user, another local account, a compromised or spoofed upstream (PyPI, Hugging Face incl. its CDN/xet redirects, GitHub releases). Out of scope: root, physical access. This order carries no token and you need none.
Read at HEAD (you cannot run git): ohyesmlx/engines.py (install_plan, _command_plan, _guided_plan, install, _real_run, _real_open, _hermetic_env, _rollback, _relocate, lab_paths, record_lab_path, _lab_paths_beside, detection helpers), fetch.py (whole), catalog.py (_REPO, _COMMIT, check_path, load), hardware.py, recommend.py; ohyesmlx/constraints/*.txt; ohyesmlx/engines-tested.json; runtimes.py `_engine_env` (lab paths become PATH for every engine start and helper command).
Questions: (1) the pip subprocess: argv, interpreter, environment (is it hermetic against pip config files such as ~/.config/pip/pip.conf and /Library/Application Support/pip/pip.conf, not only PIP_* variables?), and whether the constraints give version pins only or hashes; (2) what writing `lab-paths.json` lets someone run, and whether any value is validated beyond non-empty string; (3) URL construction and the redirect guard: any way a catalog literal or a redirect reaches a non-HF host, plain http, or a file:// handler; certificate verification under a bundled Python with no CA bundle; (4) path traversal in repo ids (`_REPO` admits `.`/`..` segments), file paths and blob keys; (5) symlink and TOCTOU races under Application Support and the HF cache (the `.incomplete` file, the snapshot link, the ledger temp file, the lock file, evict's realpath check then remove); (6) ledger trust: what a tampered `fetched.json` can make evict delete, given `HF_HUB_CACHE` may point anywhere; (7) the post-transfer snapshot-conflict check: a file appearing at the snapshot path between plan and link; (8) file modes created (venvs, logs, ledger, blobs) and whether another local account can read or write them; (9) `_rollback`'s inside-engines-dir check; (10) what a bundled Python (interpreter used for `-m venv`) exposes: user site-packages, PYTHONSTARTUP, PYTHONHOME, `-I`.
Do not re-report (known, dispositioned): UAT-001 (`fetch.downloaded` compares sizes, not hashes); no DMG checksum (the app never downloads binaries; the user drags from the vendor page); no uninstall flow; no parallel chunks or mirrors.
Report a findings table: id, file:line, actor, impact, severity (high = an in-scope actor without the token can change the machine, run code, read the user's files or delete data; medium = needs the token or a same-user process, or leaves the user's state wrong without saying so; low = defence in depth).
