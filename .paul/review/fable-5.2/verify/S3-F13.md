# S3-F13 — "Stop After This Cell" cannot be escalated to "Stop Now"

**Claim (one line):** both Benchmark toolbar buttons carry `.disabled(stopping)`, and `stopping`
is true for `.stoppingAfterCell` as well as `.stoppingNow`, so after the first press the second —
the control for a hung cell — is unreachable.

## Reproduction

This one cannot be reproduced in the kit test target: the disable is a SwiftUI modifier in the
`OhYesMLX` executable, which the tests cannot import (`app/Package.swift` makes the test target
depend on `OhYesMLXKit` only). What a test *can* settle is whether the lock is in the model.
`app/Tests/OhYesMLXKitTests/FableS3F13Tests.swift` presses "Stop After This Cell" and then "Stop
Now" through `AppModel.cancelJob`, and finds the model accepts the escalation:

```
$ cd app && OYMLX_DEV_PYTHON=…/app-dev-venv/bin/python swift test --filter FableS3F13Tests
Test Case '-[OhYesMLXKitTests.FableS3F13Tests testStopNowReachesTheBackendAfterStopAfterThisCell]' passed (0.008 s).
```

The backend received both calls (`cancelCalls == [(now: false), (now: true)]`) and the state went
`.running → .stoppingAfterCell → .stoppingNow`. So nothing below the view blocks the escalation;
the view is the whole of the finding.

## Code path, as cited — every line number verified

- `app/Sources/OhYesMLX/Screens/BenchmarkView.swift:70-91` — the run's toolbar: "Stop After This
  Cell" (`:73-80`, `.disabled(stopping)` at `:80`) and "Stop Now" (`:82-89`, `.disabled(stopping)`
  at `:89`). Neither reads the state separately; both read the same `stopping`.
- `BenchmarkView.swift:95-98` — `stopping` is `state == .stoppingAfterCell || state ==
  .stoppingNow`. The first press therefore disables both, and only `running` (`:15`) gates the
  toolbar as a whole.
- `AppModel.swift:517-529` — `cancelJob(now:)` sends the cancel and sets `.stoppingAfterCell` for
  `now: false` and `.stoppingNow` for `now: true`. It has no state guard that would refuse a
  second call while the job is still active, which is what the test shows.
- The backend keeps the two signals apart: `ohyesmlx/server.py:768-780` (`_post_job_cancel`)
  documents `{"now": true}` as setting the cancel flag *and* the abort flag, while a no-body
  cancel stops at the next between-cells check (W1 sweep line 338 quotes the same). So an
  escalation after "Stop After This Cell" is a real, different instruction, not a duplicate.
- Why the lock hurts: with a cell hung, the only remaining control is quitting. Quit with a job
  active waits `jobBound` = 150 s (`BackendLauncher.swift:28`, `:380-385`), because `requestQuit`
  passes `jobRunning = job?.state.isActive == true` (`AppModel.swift:569-570`) and
  `.stoppingAfterCell` is active (`AppModel.swift:39-41`). The only other stop control in the UI is Models'
  per-row "Cancel" (`Screens/ModelsView.swift:188-190`), which is also `now: false` and is shown
  for a download row, not for a benchmark.
- Spec check: `docs/interfaces/v5-app.md:93-95` (Jason's answer 3) pins two controls and their
  sentences; it says nothing about the first disabling the second. So the lock is not a pinned
  behaviour that the review is second-guessing.

## What I did not verify

- The screen itself: no UI run, no screenshot. The disable is read from source.
- Whether a second press while `.stoppingAfterCell` would be acted on by the backend if it did
  arrive — `server.py`'s `_post_job_cancel` reads current flags on each request, but I did not
  start a server (forbidden by the order) to see a late `{"now": true}` land.

VERDICT: CONFIRMED (no test: the `.disabled(stopping)` is a SwiftUI modifier in the `OhYesMLX` executable target, which the kit test target cannot import; the kit-level test shows the model still accepts "Stop Now" after "Stop After This Cell", so the view's single `stopping` flag is the whole of the block)
SEVERITY-CHECK: agree — Low. It needs a cell that hangs or runs long, the backend's own bound ends the run eventually, and the escape hatch (quit) exists and is merely slow; but the one control built for the moment is the one that is greyed out.
