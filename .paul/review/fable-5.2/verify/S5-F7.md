## What the code does

`ohyesmlx/osaurus_settings.py:320-328` is the real failure path this finding depends on: when
`filecmp.cmp(target, backup, shallow=False)` disagrees, `_put_back` logs
`"not byte-identical, so the backup is kept: …"`, removes nothing, and returns `False`.
`restore` returns that value unchanged (`:361`), so `False` is an ordinary, reachable return —
not an exception. `tests/test_osaurus_settings.py:300-343` already proves the real
`restore()` returns `False` on a tampered file. My harness stubs the module with exactly that
return value; it does not invent a code path.

`scripts/osaurus-pin.sh:76-82` turns that boolean into an exit status correctly —
`raise SystemExit(0 if s.restore(...) else 1)` — and the shell takes the `else` branch:

```
RESTORE FAILED: ~/.osaurus/config differs from $BACKUP_DIR -- copies kept
```

Then `:83` runs `trap 'echo "ABORTED $(date +%H:%M:%S)"; sweep; exit 130' INT TERM HUP`. That
is the function's **last command**, and `trap` returns 0, so the function returns 0. Two
consequences, both in the finding: (i) the caller's `if`/`||`/`$?` sees success after a failed
restore; (ii) the `INT TERM HUP` handler is replaced by one that never calls
`osaurus_restore`, so a later interrupt cannot retry the restore the backups still allow.

`scripts/osaurus-pin.sh:24-29` is the only restore the trap at `:32` runs. Its Python is
`s.restore('$CONFIG_DIR', backup_dir='$BACKUP_DIR')` with the result unread, and the shell's
`|| return 1` fires only when the Python *raises* — not when it returns `False`. `restore`
raises only for "no backup at all" (`osaurus_settings.py:357-360`), the one case the shell's
own `:25` guard already excludes. So on a genuine mismatch the trap path exits 0 from
`osaurus_restore` and `:32` proceeds to `exit 130`, having printed `ABORTED <time> -- restoring
Osaurus settings` and nothing about the restore.

The caller half is real too: `scripts/run_canary.sh:41-42` is `osaurus_restore_check` followed
by `echo "DONE $(date +%H:%M:%S)"`, and the script has `set -u` only (`:12`) — no `set -e` —
so the final command's status is its exit status. `run_grid_35b.sh:52` discards the status in
an `&&` list and carries on to `sleep 5`.

One nuance the fix should know, beyond the finding's wording: a fixed
`osaurus_restore_check` that merely **returns** non-zero still leaves `run_canary.sh` exiting 0
and `run_grid_35b.sh` continuing, because neither caller checks it. "Callers exit non-zero on a
failed restore" needs an edit in the callers (`|| exit 1`, or a `set -e`) as well as the return
value.
