`log` (`:948-953`), with no `summary["not_evicted"].append(leftover)` — unlike the per-cell path

## The two sites, side by side

Per-cell path, `quickbench.py:914-933` — records in **both** outcomes:

```
                try:
                    if not evict(sibling.repo, True, …):
                        note_not_evicted(sibling.repo)          # refusal -> recorded
                except Exception as error:
                    send("log", f"could not evict {sibling.repo}: {error}", …)
                    summary["not_evicted"].append(sibling.repo)  # raise -> recorded
```

Run-level sweep, `:943-953` — records only the refusal:

```
        for leftover in sorted(outstanding):
            try:
                if not evict(leftover, True, cache_dir=cache_dir, emit=_discard):
                    note_not_evicted(leftover)                   # refusal -> recorded
            except Exception as error:
                send("log", f"could not evict {leftover}: {error}", …)
                                                                 # raise -> NOT recorded
```

`note_not_evicted` (`:622-629`) is the one helper that appends and logs; the sweep's except
block logs its own line and skips the append.

## Why it matters beyond a missing log line

`not_evicted` is not an internal detail: it is the pinned summary field the app renders as
"Left on disk: <title> (<size>) — it was in use. You can remove it from Models."
(`app/Sources/OhYesMLXKit/AppModel.swift:273-278`, read in `ResultsView.swift:37-39`; the field
is decoded at `Models.swift:716, 734`). An empty list therefore tells the user, on the Results
screen, that nothing was left behind — while the sibling is still on disk and still in the
fetch ledger.

The raising cases are ordinary: `evict` refuses with `ledger_unreadable` on a ledger it cannot
parse (`fetch.py:1224-1226`) or on a ledger path outside the repo (`:1236-1244`), and raises on
any unexpected OS error while it rewrites the ledger. The host's real `fetched.json` is known to
be polluted (dossier-S4.md:323: "its one entry lists 60 paths under two `/private/tmp/...`
scratch caches … both the old and the new containment checks refuse it"), which makes a
refusal — and a `busy`-then-raise sequence — a live possibility on this machine.
