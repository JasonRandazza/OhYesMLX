# S2-F6 — a transport-failed row is published as "coherence: pass"

**Claim (one line):** when any measured request fails in transport, `measure._set_status`
returns before `_incoherent` runs, so the row's reason is a transport count and
`report._floor_verdicts` renders the coherence floor as **pass** — a gate that never judged the
row, and on a row whose surviving responses are garbage.

**Verdict:** reproduced, in both directions the finding names.

## Code path

- `ohyesmlx/measure.py:1236-1245` — `failures = [o for o in result.observations if not
  came_back(o)]`; `if failures:` sets `FAIL` with
  `"{n} of {m} measured requests failed; first: {o.error}"` and **returns**.
- `ohyesmlx/measure.py:1253-1259` — the comment says the gate runs before the metric check so
  garbage is not buried, and `_incoherent` is called at `:1256`. The transport branch above it
  returns first, so the gate never runs on any row with a failed request.
- `ohyesmlx/measure.py:1311-1342` — `_incoherent` already skips the responses that did not come
  back (`if not came_back(observation): continue`, `:1330-1331`) and judges a majority of the
  rest. Handed the same observation list directly it returns
  `'incoherent output: replacement characters'`, so the information the gate needs is present in
  the row and is simply never asked.
- `ohyesmlx/report.py:1097-1106` — `_coherence_failed(status, reason)` (`:1133-1143`) identifies
  the coherence gate **by its vocabulary**: `reason.startswith(measure.INCOHERENT_PREFIX) or
  reason == measure.STILL_THINKING`. A transport reason matches neither, so control falls to the
  `elif status != "PASS"` branch, which is
  `[_verdict("coherence", "pass"), _verdict("metrics", "fail", reason)]`.
- `ohyesmlx/report.py:713-716` — the card prints those verdicts verbatim, so the rendered card
  carries `| floor coherence | pass | |` beneath `| status | FAIL | 1 of 9 measured requests
  failed… |`.

The "not reached" state the finding points at is real and already used in the other direction:
`report.py:159-161` defines it ("a gate an earlier failure never got to") and `:1098-1101` emits
it for `metrics` on a coherence failure. The transport branch is the one place the direction is
not mirrored.

## Reproduction

New file `tests/test_fable_s2_f6.py` (the only file added besides this report). Each case builds
a real `measure.CellResult`, runs the real `measure._set_status`, and summarises with the real
`report.summarize`; no runtime, no model, no network.

Failure text:

```
AssertionError: a row whose eight surviving samples are token salad is published as
coherence: pass (detail None) under the reason '1 of 9 measured requests failed; first:
TransportError: timeout after 600s'; the gate never ran on it and the garbage it exists to
catch is on the record
assert 'pass' != 'pass'

AssertionError: nine failed requests are published as coherence: pass (reason '9 of 9 measured
requests failed; first: TransportError: timeout after 600s')
assert 'pass' != 'pass'
```

The tests assert `floor["state"] != "pass"` rather than a specific replacement, so either fix
shape the finding names satisfies them: running `_incoherent` over the survivors (yielding
`coherence: fail` with the gate's own reason), or reporting `coherence: not reached` for a
transport/start failure. I did not change any code.

The third case the finding names — "runtime did not start" — needs no separate test: the same
`elif` handles it, and I observed it directly. A row whose second visit's `start()` raised, with
three healthy samples, has `reason = "runtime 'mlxlm' did not start: RuntimeError: port still
held"` and `floors = [('coherence', 'pass'), ('metrics', 'fail')]`.

## What I did not verify

- I did not change `_set_status` or `_floor_verdicts`; the tests are red on the current code by
  design (verify role).
- I did not decide which of the two fix directions is right. Running the gate over the survivors
  makes a timeout+garbage row FAIL on coherence, which loses the transport failure as the row's
  headline reason; "not reached" keeps the transport reason and drops the claim. Both are
  defensible and it is a coordinator call.
- I did not check whether any published column on disk was produced with a mixed
  failure+garbage row, so I cannot say whether a published table already shows this label.
