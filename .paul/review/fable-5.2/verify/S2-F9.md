# S2-F9 — a header with no `harness` key is skipped, so a pre-stamp run joins a stamped one

**Claim (one line):** `report._check_harness` does `harness = header.get("harness")` and
`continue`s when it is `None`, so a column written before `harness.source_sha256` existed joins a
column measured this week with nothing compared and nothing said.

**Verdict:** reproduced.

## Code path

- `ohyesmlx/report.py:1497-1510` — the whole guard:

  ```python
  seen = None
  for label, header, _rows in runs:
      harness = header.get("harness")
      if harness is None:
          continue                       # :1501-1502 -- the hole
      source_sha256 = harness.get("source_sha256")
      if seen is not None and seen[1] != source_sha256:
          raise ValueError(...)          # only between two stamped headers
      if seen is None:
          seen = (label, source_sha256)
  ```

  A legacy header never sets `seen`, never compares, and never appears in a refusal.
- `ohyesmlx/report.py:525` — `_check_harness` is the first guard `render_grid` runs; there is no
  second pass over the headers anywhere.
- `ohyesmlx/report.py:1729-1736` — `_harness_provenance` also filters on
  `header.get("harness") is not None`, so the rendered "Harness … for `<label>`" lines appear only
  for the stamped columns. The mixed grid's provenance block names one column and silently omits
  the other, which a reader can easily read as "one harness" rather than "one unknown".
- `docs/interfaces/grid-and-warmup.md:96-101` — the contract states the skip as deliberate for the
  all-legacy case: "a header predating the block carries none and is skipped. Two revisions of the
  loop are not one grid." The last sentence is the rule the mixed join breaks.

`measure._source_sha256` (`measure.py:436-440`) hashes every `ohyesmlx/*.py`, so any commit
touching the package changes the stamp. A 2026-09-16 column and a 2026-11 column are different
source by construction, which is the finding's premise and is not in dispute.
