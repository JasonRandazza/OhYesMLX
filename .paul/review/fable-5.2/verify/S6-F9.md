# S6-F9 — verification

**Claim, restated in one line:** no gate exercises the path a downloader takes — a quarantined
zip unpacked by Archive Utility and launched from Downloads — so three properties are asserted
without an observation: the translocation screen under real translocation, that the approved app
may exec the quarantined bundled `python3` and import from `Contents/Resources`, and
`gatekeeper.md:45`'s "macOS asks again".

## What the code does (line numbers verified in this worktree)

The release artefact is a zip of a locally built, never-quarantined bundle:

- `scripts/build_app.sh:36` — `ZIP="$DIST/OhYesMLX-$VERSION.zip"`; `:124-126` — `ditto -c -k
  --keepParent "$APP" "$ZIP"`. Nothing between assembly and zipping touches extended attributes,
  so the zip carries no `com.apple.quarantine` and the `$APP` it is made from has none either
  (it was produced in `dist/` on the build machine).

The only bundle gate opens that unquarantined bundle from an image it just made:

- `scripts/check_bundle.sh:143` — `hdiutil create -quiet -srcfolder "$APP" -format UDRO …`;
  `:149` — attach read-only; `:158` — `open "$MOUNT/OhYesMLX.app"`. An image built from `$APP`
  inherits no quarantine, so `open` never causes translocation and never shows Gatekeeper's
  first-launch dialog.

The clean-account smoke exercises a wheel, not the app:

- `scripts/smoke_clean_account.sh:8` — "the wheel from `git archive HEAD`"; `:153-154` —
  `uv build --wheel`; `:163` — `pip install --no-deps --no-index "$SMOKE"/dist/*.whl`. The
  string `.zip` does not occur in the script, and neither does `unzip` or `xattr`.

Nothing in `scripts/` mentions quarantine at all:

```
$ grep -rn "xattr\|quarantine" scripts/
(none)
```

The translocation guard is tested by injecting a path string, not by launching a translocated
copy:

- `app/Sources/OhYesMLXKit/AppModel.swift:255-257` — `isTranslocated(bundlePath:)` is
  `bundlePath.contains("/AppTranslocation/")`; `:259-261` — `translocated`.
- `app/Tests/OhYesMLXKitTests/AppModelTests.swift:274-275` — the test passes the literal
  `"/private/var/folders/xy/T/AppTranslocation/8F2C-9A1B/d/OhYesMLX.app"` and asserts the guard
  fires. That proves the predicate; it does not prove macOS produces such a path for this bundle
  or that the move screen appears when it does.

`docs/release/gatekeeper.md:45` — "You only do this once per copy of the app. If you move or
replace the app, macOS asks again." — is unverified by anything in the repo: no run moves a
quarantined copy and observes a second prompt.

It asserts: no file under `scripts/` contains `xattr` or `quarantine`; `check_bundle.sh` builds

`smoke_clean_account.sh` builds and installs a `*.whl` and never mentions `.zip`/`unzip`; the

Red-check (the test is a characterisation of an absence, so the check is that it bites when the

`AssertionError: a gate now touches quarantine: ['check_bundle.sh']`; restored, it passes. No
repository file was edited for this.

## What is not verified

- Nothing was quarantined, unzipped, moved, or launched. No zip exists in this worktree
  (`dist/` is not present), and running the step would need the GUI, Archive Utility, and an
  interactive Gatekeeper approval — the order forbids launching the app.
- Whether the second-half failure (a quarantined bundled `python3` refused exec or failing to
  import from a read-only translocated path) actually happens is **unknown**. That is the
  finding's own position, and it is the reason to run the step once before the first release.
- Whether macOS re-prompts after the move (`gatekeeper.md:45`) is likewise unobserved.
- No transcription line exists in any repo document, so the fix direction's transcript has no
  home yet; where it should be recorded is the coordinator's call.
