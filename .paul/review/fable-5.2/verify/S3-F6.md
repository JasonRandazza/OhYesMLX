# S3-F6 — `start()` does its destructive bookkeeping before the slot is claimed

**Claim (one line):** `AppModel.start` resets per-kind state and writes `inflightJob` before
`POST /jobs` claims the slot, so a second start that the backend refuses deletes the first
job's crash record, a refused benchmark start has already wiped the run on screen, and the
refusal it sets is rendered only by `EnginesView`.

**Verdict:** reproduced, deterministically, on unchanged code — two tests, both red. The
double-entry window is real and the model permits it (`canStartJob` stays `true` while the
first POST is in the air, and every start control is only `.disabled(!model.canStartJob)`).
The loser's catch deletes the winner's record, and a running job is left with no crash record
behind it. The benchmark half needs no race at all: a refused start clears `summary`,
`summaryData` and `liveCells` and sets no `benchmarkRefusal`, so the Results screen empties and
the Benchmark screen shows no reason.

## Code path (unchanged `AppModel.swift`)

- `app/Sources/OhYesMLXKit/AppModel.swift:607-623` — `start` clears `refusal` (`:610`), then for a
  quickbench clears `benchmarkRefusal`, `liveCells`, `summary`, `summaryData` (`:612-615`), for an
  install clears `engineFailures[name]` (`:617`), otherwise clears `modelRefusals[name]` (`:619`),
  and **then** writes `inflightJob` (`:622-623`) — all before the POST.
- `AppModel.swift:626-635` — `try await backend.startJob` (`:627`); a `BackendError` sets only
  `refusal` and removes `inflightKey` (`:628-631`); the non-`BackendError` catch removes the key
  and sets nothing at all (`:632-635`). Either way the winner's record is gone.
- `AppModel.swift:637-644` — `job` is assigned only after the POST returns, which is why the slot
  looks free for the whole round trip. `oneSlotReason` (`:263-267`) and `canStartJob` (`:269-271`)
  read `job.state.isActive`, so they answer "free" during that window.
- Every start control is gated only by that predicate: `EnginesView.swift:170`, `:194`;
  `ModelsView.swift:224`, `:240`; `BenchmarkView.swift:249`. Enabled during the in-flight POST.
- `AppModel.swift:782-791` — `loadInflight` is what `launch` (`:382`) turns into
  `interruptedJob`, so the deleted key is exactly the crash-recovery record: a crash after the
  loser's catch leaves no interrupted banner.
- Refusal rendering: the only reader of `model.refusal` in the app is
  `app/Sources/OhYesMLX/Screens/EnginesView.swift:17`. Models renders
  `model.modelRefusals[pick.modelID]` (`ModelsView.swift:149`) and Benchmark renders
  `model.benchmarkRefusal` (`BenchmarkView.swift:39`); neither is set by a *start* refusal.

Both halves are visible in Test B's passing/ failing split: `refusal?.code == "busy"` is set
(passes) while `summary`, `summaryData` and `benchmarkRefusal` are all `nil` (fail).

## What I did not verify

  alternate route in the finding (Retry on the interrupted banner while another control is
  pressed) hits the same funnel at `retryInterrupted` (`:546-560`) and is not separately tested.
- The connection-failure variant of the benchmark wipe (`catch` at `:632-635`). It follows from
  the same line numbers — the reset precedes the POST and the catch sets nothing — but I did not
  write a backend that throws `URLError` to drive it, so that half is read, not run.
- No screenshot or UI run; `EnginesView.swift:17` and the absence of any other `model.refusal`
  reader were established by grep across `app/Sources/OhYesMLX/`, not by launching the app.

## Note for whoever fixes it
