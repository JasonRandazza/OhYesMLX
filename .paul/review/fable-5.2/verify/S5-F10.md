# S5-F10 — verification

**Claim, restated in one line:** `lsof`, `ps` and stop commands are run through `_engine_env`, so
one engine's lab-path defect either turns a stop into an unrefusable-looking refusal
(`RuntimeStartError` → `None` → "cannot identify listeners") or kills it outright with an
uncaught `ValueError`, and the same unconditional loop refuses one engine's start with a message
naming another.

Three separable claims; each was tested.

## What the code does (line numbers verified in this worktree)

- `ohyesmlx/runtimes.py:471-531` `_engine_env` — walks **every** `manifest` entry (`:511`), takes
  no engine identity, raises `RuntimeStartError` at `:514-519` for a lab path with nothing at it,
  and lets `lab_paths`' `ValueError` out (`:521-522`); builds one combined `PATH` at `:530`.
- `ohyesmlx/runtimes.py:569-585` `_run` — `env = _engine_env()` inside the `try` (`:572`);
  `except (OSError, subprocess.SubprocessError, RuntimeStartError): return None` (`:584`).
  `ValueError` is not in that tuple.
- `ohyesmlx/runtimes.py:691-711` `_listener_pids` → `_run` → `None` when `_engine_env` refuses.
- `ohyesmlx/runtimes.py:1656-1684` `_shutdown` — `listeners is None and stop_command` raises
  `RuntimeStopError("cannot identify listeners on port ...; refusing handoff cleanup")`
  (`:1666-1670`).
- `ohyesmlx/runtimes.py:1981-1990` `Handle.stop` — no `except`.
- `ohyesmlx/runtimes.py:1908-1937` `stop_own_engines` — `except RuntimeStopError` only (`:1931`),
  run as the "Stop now" daemon thread (`server.py:803-808`).
- `ohyesmlx/runtimes.py:2288-2292` `Runtime.start` — `if not _port_is_free(self.port)` is the
  first check, so the same `None` refuses a **start** too.
- `ohyesmlx/runtimes.py:678-690` `_port_is_free` — `result is None` answers `False` ("'unknown'
  has to mean 'not free yet'").
- `ohyesmlx/runtimes.py:1827-1864` `_stop_orphan` — `if listeners is None: return`
  (`:1843-1844`), and `stop_orphaned_engines` unlinks the ledger unless a `RuntimeStopError` was
  raised. That half is S5-F4's finding; it is named here only as the consequence `None` feeds.
- `cli.py:1077-1080` wraps launch recovery in `except Exception`.

## Clause by clause

1. **`lsof`/`ps` run under the lab environment — CONFIRMED.** `_run:572` takes `_engine_env()`.
2. **One lab defect disables stopping for every engine — CONFIRMED, and wider than stated.**
   The finding says the refusal hits "every engine that has a stop command". Only **Osaurus** has
   one (`runtimes.py:2556-2557`; mlxlm/omlx/optiq/vmlx/mtplx return `()`), so that scope is one
   engine. The other five take the `stop_command`-empty branch and lose differently: `None` makes
   `_port_is_free` answer "busy", so `await_port_free` polls for the whole `STOP_TIMEOUT_S` and
   then raises anyway — measured at 30.0 s. The defect reaches all six engines by two paths.
3. **Invalid JSON kills a stop outright — CONFIRMED.** `ValueError` is outside `_run`'s catch
   tuple; `Handle.stop` has no handler; `stop_own_engines` catches only `RuntimeStopError`.
4. **A missing lab copy refuses another engine's start, naming the wrong engine — CONFIRMED.**
   An Osaurus spawn is refused with a message about OptiQ.
5. **"launch recovery ... die[s] with a traceback" — REFUTED.** `cli.py:1077-1080` catches
   `Exception` around `stop_orphaned_engines` and emits `orphan_stop_failed`. Launch recovery
   survives; what it leaves behind is F4's silent ledger unlink, not a traceback.
6. **`Handle.stop` "dies with a traceback" — partly REFUTED.** `Handle.stop` raises the
   `ValueError` uncaught (confirmed directly). The caller decides what that becomes:
   `measure.run_cells` re-raises every `BaseException` from a visit (`:650-653`), so a CLI grid
   aborts the run; quick-bench's per-cell `except Exception` (`quickbench.py:703-706`) turns it
   into a `FAIL` cell and the cell loop continues. Neither is an unhandled traceback, and in
   neither is the engine signalled — so the hazard the severity rests on ("an engine that cannot
   be stopped keeps its weights") stands.

Not in the finding, found while testing: the same `None` also refuses **starts**, with a
refusal naming a listener that is not there (`:2288-2292`). This widens the blast radius from
"cannot stop" to "cannot start either".

## Red-check (performed)

Reverted the defect by replacing `_run`'s `env = _engine_env()` with `env = dict(os.environ)` —
the finding's own fix direction. Result: **5 of the 6 tests go green**
(`listener probe`, `stop not refused`, `port probe`, `start not refused`,
`stop_own_engines`). Only `one_engines_missing_lab_copy_does_not_refuse_another_engines_start`
still fails, which is correct: that clause needs F1's per-engine identity, not a plain helper
environment. The file was then restored; `git status --short ohyesmlx/` is empty and
`git diff ohyesmlx/` shows nothing.

## What is not verified

- No engine was started and no real engine pid was signalled. The pids are reaped children; the
  ports are sockets bound and closed inside the test.
- The trigger was written directly — a lab entry pointing at a directory that does not exist, and
  a file containing `{`. How often a user reaches that state is S1-F7 / S4-F2's question.
- The `ps` half of the finding follows the same `_run` path and was not tested separately; the
  `lsof` half exercises the same code.
- The claim that quick-bench measures the next cell beside a survivor is F3's, not tested here;
  it is named only as a consequence, not asserted.
