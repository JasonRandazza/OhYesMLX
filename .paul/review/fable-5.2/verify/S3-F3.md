# S3-F3 — a failed Osaurus restore is neither unstated nor summary-detected

**Claim (one line):** when the Osaurus pin's restore fails, nothing tells the user — Results
says the run "ended without a result", no view reads `summary.osaurus`, the stage-B note is
written only when stage B never started — and the failure is recognised only by the whole
typed `QuickSummary` decode, so a backend field rename makes the job read `.finished` and
Results say the run "has not finished yet".

## Cited code, verified at those lines in this tree

- `app/Sources/OhYesMLXKit/AppModel.swift:675-682` — `.done` computes
  `status.kind == .quickbench && summary?.ended == .restoreFailed` and sets `.failed` only
  when `status.state.isActive`. Cited correctly.
- `AppModel.swift:700-702` — `.result` stores `event.payloadData` and assigns
  `summary = summaryData.flatMap { try? JSONDecoder().decode(QuickSummary.self, from: $0) }`.
  Cited correctly.
- `AppModel.swift:689-699` — **the event the finding omits.** `.error` sets
  `status.state = code == "cancelled" ? .cancelled : .failed`, stores `refusal`, and calls
  `route`. `route` (`:731-737`) puts a non-cancelled quickbench error into `benchmarkRefusal`.
- `app/Sources/OhYesMLX/Screens/BenchmarkView.swift:39-40` — `if let refusal =
  model.benchmarkRefusal { refusalSection(refusal) } else if let plan = model.quickPlan`;
  `:115-128` renders `refusal.message` with a warning glyph. So `benchmarkRefusal` is a
  user-visible banner that *replaces* the plan.
- `app/Sources/OhYesMLX/Screens/ResultsView.swift:18-57` — summary branch first; `:45-51`
  the "This run has not finished yet; its cells appear here as they land." branch when
  `summary == nil` and `liveCells` is non-empty; `:110-114` the
  "cancelled / ended without a result" line when `summary.best == nil`.
- `BenchmarkView.swift:218-221` and `:274-278` — the two unconditional promises: "Your
  settings are put back when the run ends or is stopped" and "Either way, Osaurus settings
  are restored." Cited correctly.
- `ohyesmlx/quickbench.py:707-740` — in `measure_cell`'s `finally`: a restore that is not
  byte-exact with `pinned` true sets `summary["osaurus"] = {restored: false, reason: …}`,
  appends `restore_failure`, **and sends `error` with `code: "restore_failed"` and
  `backup_dir`** — before the cell's record, the summary or the ending.
- `quickbench.py:805-807` (stage A) and `:931-933` (stage B) — `ended = "restore_failed"`
  is set only after a loop iteration when `restore_failure` is non-empty, i.e. only after
  the error above was sent. The module's own contract states the order at `:532-535`:
  "A restore that does not verify … ends the run with an ``error`` naming the backup
  directory and a summary that records it."
- `quickbench.py:1002` — the one `result` (the summary). `:1012-1018` — the `done`
  "quickbench stopped after a failed Osaurus restore".
- `quickbench.py:981-991` — the stage-B note "stage B was not run: the run stopped after a
  failed Osaurus restore" is written only when `stage_b.engine is None and note is None`.
  A stage-B restore failure leaves the record without that note; a stage-A failure gets it.
- `ohyesmlx/cli.py:1064-1105` — `_recover_startup` recovers `quickbench.DEFAULT_BACKUP_DIR`
  (the same directory an app run uses: `quickbench.py:95`, `:514`) on the next launch when
  the Osaurus app is not running, and reports only as stderr JSON (`recovered` /
  `recovery_failed` / `recovery_pending`). The app shows stderr only on the backend-stopped
  screen (`FullWindowStates.swift:96-121` via `RootView.swift:11`).

## Method

New file `app/Tests/OhYesMLXKitTests/FableS3F3Tests.swift`, three tests driving the
production `AppModel` with `StubBackend` and the pinned fixture
`quickbench_summary_finished.json`, mutated into the record a stage-B restore failure
leaves (`ended: restore_failed`, `best: null`, `osaurus.restored: false` with the
backend's reason, no stage-B note).

1. **The backend's stream**, with one required key renamed (`label` → `cell_label` inside a
   stage-A cell, the kind of backend change the finding names): `error(restore_failed)` →
   cell `progress` → `result` → `done`, the order `quickbench.py` produces.
2. **Control:** the same record plus an *added* unknown field (`future_field`).
3. **The finding's stream:** `progress` → `result` (renamed key) → `done`, with no error
   event — the only stream on which the `.done` branch's summary reader decides the state.

Run: `cd app && OYMLX_DEV_PYTHON=$HOME/.local/share/ohyesmlx/app-dev-venv/bin/python swift test --filter FableS3F3Tests`

Before settling on the final file I ran the first test as `result → done` with the renamed
key (the finding's modelled stream): it failed exactly as the finding describes —
`XCTAssertEqual failed: ("Optional(JobState.finished)") is not equal to
("Optional(JobState.failed)")`. Rewriting the stream to the backend's own order turned it
green with no production change, which is the refutation: the `.finished` state depends on
dropping the event the backend documents itself as sending.

## What the finding gets right, and what remains

- `summary.osaurus` is decoded and read by no view: grep of `app/Sources` finds the type
  and its `CodingKeys`/`init` in `Models.swift:683-705` and the stub fixture
  (`StubBackend.swift:835`) only.
- `job.message` renders only at `EnginesView.swift:145` (install rows); `JobState.failed` is
  rendered nowhere (`state.text` appears only for the two stopping states,
  `BenchmarkView.swift:268-271`). Both verified by grep.
- The Results screen, where a finished quickbench sends the user (`AppModel.swift:685-687`),
  never states the restore failure and states something false: with a decodable summary,
  `best == nil` gives "This run ended without a result; nothing is recommended from it."
  (`ResultsView.swift:110-114`; `best` is nulled for any non-finished run,
  `quickbench.py:994-996`); with a summary the app cannot decode it falls to "This run has
  not finished yet; its cells appear here as they land." (`ResultsView.swift:45-51`), with
  the model facts my first test pins (`summary == nil`, `liveCells` non-empty). The restore
  statement is one navigation away on Benchmark, not on the screen the user lands on.
- The two Benchmark promises are unconditional while the code can fail to keep them
  (`BenchmarkView.swift:218-221`, `:274-278`) — the fix direction's "soften the copy" points
  at a real overclaim.
- A stage-B restore failure really does leave the summary with no line naming it
  (`quickbench.py:981-991`); a stage-A failure does get the note, which Results renders under
  Stage B.
- The typed decode is all-or-nothing and a rename does nil `summary`, so any Results
  presentation that needs `ended`/`osaurus` must read the raw payload (the finding's fix
  direction). But the *state* does not depend on it, and the record the app already exports
  (`summaryData`) still carries `"ended": "restore_failed"`.
- `_recover_startup` may repair the pin on the next launch when the Osaurus app is not
  running; its outcome is a stderr line no normal screen shows. That lowers the harm, as
  the finding's confidence note suspected, and it does not change any statement the app
  makes during the run.

## What the finding gets wrong

1. **"never stated to the user"** — false. The backend's `error` event is stored in
   `benchmarkRefusal` (`AppModel.swift:689-699`, `:731-737`) and rendered as a warning
   banner on Benchmark (`BenchmarkView.swift:39-40, 115-128`) with the exact message
   including the backup directory where the originals are. The finding quotes only
   `job.message`'s lone renderer and `summary.osaurus`, missing the refusal banner.
2. **"the job reads `.finished`"** — false on the backend's stream. The `.error` event
   arrives before the `result` and the `done` and sets `.failed`; the `.done` branch only
   writes a state when the job is still active (`AppModel.swift:676-681`). The earlier
   red run above shows `.finished` only when that event is deleted from the stream.
3. **"one added … backend field makes `try?` return nil"** — false for *added* fields.
   `JSONDecoder` ignores keys a `Codable` type does not name, which
   `testACancelledSummaryTypesAndKeepsItsRawBytes` (`AppModelTests.swift:785-799`) already
   pins for `future_field`, and test 2 pins again here. A *renamed*, removed or
   type-changed key does break it.
4. Minor: `QuickSummary` has 14 required keys, not 16 — `actual_s` and `best` are optional
   (`Models.swift:707-742`); `label`/`reused` (`QuickCell`, `:580-581`) and `tie`
   (`QuickStageA`, `:630`) are indeed non-optional.
