# S3-F2 — any job's `result` overwrites the benchmark summary

**Claim (one line):** `AppModel.apply`'s `.result` branch (`AppModel.swift:700-702`) has no
`args.kind == .quickbench` guard, so the `result` event a download, evict or install emits
replaces a finished quickbench's `summaryData` with the job's own receipt and nils `summary`;
Results then renders its live-cells branch ("This run has not finished yet", false) and Export
stays enabled, writing the receipt as `OhYesMLX-quickbench-<stamp>.json`.

**Cited code, verified at those lines in this tree:**

- `app/Sources/OhYesMLXKit/AppModel.swift:700-702` — `case .result: summaryData = event.payloadData;
  summary = summaryData.flatMap { try? JSONDecoder().decode(QuickSummary.self, from: $0) }`. No kind test.
- `AppModel.swift:703-706` — `.progress` immediately below *does* guard on
  `args.kind == .quickbench`.
- `AppModel.swift:675-682` — `.done`, the w2 fix, guards only the `restoreFailed` reading
  (`status.kind == .quickbench && summary?.ended == .restoreFailed`); the `.result` reader was
  left unguarded, exactly as the finding says.
- Receipt emitters: `ohyesmlx/fetch.py:883` (`already_present`), `:1172-1176` (`downloaded`),
  `:1302-1306` (evict), `ohyesmlx/engines.py:1317-1320` (install). `ohyesmlx/quickbench.py:1002`
  is the legitimate summary.
- View: `app/Sources/OhYesMLX/Screens/ResultsView.swift:18` (summary branch first), `:45-51`
  (live-cells branch and the "not finished yet" line), `:72` (Export disabled only when
  `summaryData == nil`), `:195-205` (writes `model.summaryData`; filename
  `OhYesMLX-quickbench-\(stamp()).json` at `:199`).

## Method

The finding's own test idea, in a new file `app/Tests/OhYesMLXKitTests/FableS3F2Tests.swift`
(3 tests), driving the production `AppModel` with the project's `StubBackend` and fixtures:

1. Finish a quickbench whose stream is the real shape — one `progress` cell, then the
   `quickbench_summary_finished.json` fixture as `result`, then `done` — and capture
   `summaryData` (4285 bytes). The test also asserts the precondition `liveCells` is non-empty,
   which is the state a real run leaves behind (`liveCells` is only cleared when the *next*
   quickbench starts, `AppModel.swift:611-615`; `.result` never touches them).
2. Enqueue the later job's stream with the receipt payload transcribed verbatim from its
   emitter (download: `{"status": "downloaded", "repo": …, "bytes": …}`; evict:
   `{"repo": …, "removed": […], "kept": […]}`; install: `{"installed": true}`), then `done`.
3. Assert the finished summary and its export bytes survive the job.

Run: `cd app && OYMLX_DEV_PYTHON=… swift test --filter FableS3F2Tests`

`testADownloadResultDoesNotReplaceTheBenchmarkSummary`:

```

FableS3F2Tests.swift:108: XCTAssertEqual failed: ("Optional(76 bytes)") is not equal to
("Optional(4285 bytes)") - Export would write the download receipt, not the benchmark summary
(ResultsView.swift:72, 195-205)
```

`testAnEvictResultDoesNotReplaceTheBenchmarkSummary`: same nil summary; `summaryData` became
**83 bytes** (the evict receipt) against the 4285-byte summary.

`testAnInstallResultDoesNotReplaceTheBenchmarkSummary`: same nil summary; `summaryData` became
**18 bytes** (`{"installed":true}`) against 4285.

The 76-byte payload is exactly the download receipt Export would write: 1234 bytes it is not,
under a filename that says "quickbench". After each job's `.result`, `model.summary == nil` and
`model.liveCells` is still non-empty, so `ResultsView` skips the summary branch and skips
`liveCells.isEmpty`'s "no run" branch, landing on `:48-51`: the "This run has not finished
yet; its cells appear here as they land." text over the finished run's rows.

## Downstream consequences in the code (match the finding)

- Results is false until another quickbench: nothing restores `summary` except a new quickbench
  `result` (`AppModel.swift:700-702` is the only writer; `start` nils it at `:611-615`).
- Export is enabled throughout: its only disabled condition is `model.summaryData == nil`
  (`ResultsView.swift:72`), and a receipt is non-nil `Data` (`Models.swift:499-506` re-serialises
  any payload). Pressing it writes the receipt bytes (`:196`) to
  `OhYesMLX-quickbench-<stamp>.json` (`:199`).
- The triggering step is the natural one: `download`/`evict` start without touching
  `summary`/`summaryData` (`AppModel.swift:616-620` only clears per-kind refusal state), and the
  one-slot gate is open once the quickbench is `.finished` (`:263-271`).
