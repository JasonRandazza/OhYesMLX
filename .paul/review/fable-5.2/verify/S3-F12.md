# S3-F12 — a backend that exits after "Quit anyway" is offered drops the quit, and the banner mislabels the wait

**Claim (one line):** (a) when `requestQuit` returns `.stillRunning` it clears `quitInProgress`
and never replies to AppKit's `.terminateLater`; if the backend then exits, `backendExited` only
sets `backendStopped` and the whole shell — including the "Quit anyway" button — is replaced by
"The backend stopped" + Relaunch. (b) The quit banner says "Finishing <kind> <repo id>…" whenever
`job` is non-nil, including a job that finished long ago, and it says "Finishing" while the
backend is cancelling the job.

## Reproduction

`app/Tests/OhYesMLXKitTests/FableS3F12Tests.swift`, one test: a `BackendRunner` whose `quit`
answers `.stillRunning`, then `backendExited(status: 0, stderrTail: [])`, then the model's own
quit state and `onQuitComplete` are checked. `onQuitComplete` is the only reply path for
`.terminateLater` (`OhYesMLXApp.swift:83-85`).

```
$ cd app && OYMLX_DEV_PYTHON=…/app-dev-venv/bin/python swift test --filter FableS3F12Tests
FableS3F12Tests.swift:52: error: XCTAssertTrue failed - the app was asked to quit and the backend
  has now exited; it must not keep running
FableS3F12Tests.swift:56: error: XCTAssertEqual failed: ("0") is not equal to ("1") -
  AppKit's .terminateLater is only replied to through onQuitComplete
Test Case '-[OhYesMLXKitTests.FableS3F12Tests testBackendExitingWhileQuitAnywayOfferedCompletesTheQuit]' failed (0.002 s).
```

`XCTAssertEqual(model.backendStopped, 0)` and `XCTAssertTrue(model.quitAnywayOffered)` passed
before those two, so the state is exactly the finding's: quit offered, backend gone, quit pending.

## Code path, as cited — every line number verified

**(a) the dropped quit.**

- `AppModel.swift:562-577` — `requestQuit` sets `quitInProgress = true`, awaits
  `runner.quit(jobRunning:)`, and on `.stillRunning` does `quitInProgress = false;
  quitAnywayOffered = true; return` (`:571-574`). It does not call `finishQuit()`.
- `AppModel.swift:531-533` — `backendExited` guards on `!quitInProgress`; after the reset above
  the guard passes and it sets `backendStopped = status` (and marks an active job `.interrupted`,
  `:535-538`). Nothing consults `quitAnywayOffered`.
- `AppModel.swift:584-589` — `finishQuit()` is the only writer of `shouldExit` and the only
  caller of `onQuitComplete`, wired in `OhYesMLXApp.swift:83-85` to
  `NSApp.reply(toApplicationShouldTerminate: true)`. `OhYesMLXApp.swift:88-95` returns
  `.terminateLater` and leaves the reply to that callback.
- `RootView.swift:10-13` — `if let status = model.backendStopped` renders
  `BackendStoppedStateView` *instead of* `shell`. The "Quit anyway" banner lives inside `shell`
  (`RootView.swift:142-154`, from `lifecycleBanners` at `:124-155`), so it disappears with it.
  `Screens/FullWindowStates.swift:96-131` is the replacement: text, stderr, "Copy details", and
  one **Relaunch** button (`:123-126`).
- Relaunch is `AppModel.relaunch()` (`:386-408`), which starts a fresh backend in an app the user
  asked to quit.
- Honest qualification: the app is not permanently unquittable. A second Cmd-Q re-enters
  `applicationShouldTerminate` → `requestQuit`; by then the child is gone, so `quitWait`'s
  `waitForExit` returns true immediately (`BackendLauncher.swift:380-390`) and the quit finishes.
  What is lost is the first quit and the visible "Quit anyway" control, which is the finding.

**(b) the mislabelled banner.**

- `RootView.swift:126-141` — `if model.quitInProgress { … if let job = model.job { Text("Finishing
  \(job.kind.wireName) \(job.name)…") } else { Text("Finishing…") } }`. The condition is a
  non-nil `job`, not `job.state.isActive`.
- `AppModel.swift:668-688` — `job` survives completion: `.done` writes `.finished` back into
  `job` (`:676-683`) and never clears it; only `relaunch` does (`:395`). So a job that finished an
  hour ago is "Finishing …" the moment a quit starts.
- `AppModel.swift:637-645` — `JobStatus.name` is `args.name`, i.e. the repo id, not the pick
  title. The display-name mapping exists (`AppModel.displayName(for:)`, `:297-299`) and the
  interrupted banner uses it (`RootView.swift:45-53`); the quit banner does not.
- "Finishing" while the job is being cancelled: `BackendLauncher.swift:380-387` — `quitWait`
  closes stdin first. `ohyesmlx/cli.py:1157` starts `_stop_at_eof` (`:1184-1205`), which calls
  `listener.shutdown()` and then `listener.jobs.cancel_and_wait(server.JOB_SHUTDOWN_WAIT_S)`
  (`cli.py:1168`, 120 s at `server.py:76`). So with a job active the app's 150 s wait
  (`BackendLauncher.swift:28, 383-385`) is spent watching a job the backend is *cancelling*, not
  finishing.

## What I did not verify

- (a)'s trigger timing. It needs a backend that overruns its own bound and then exits; the test
  calls `backendExited` directly rather than making a real child do that. The state-machine half
  — the missing reply — is what the test proves.
- (b) needs the app running; the banner is SwiftUI in the executable target, which the test target
  cannot import. It is cited, not exercised.
- I did not run the app to see the "The backend stopped" screen replace the shell.
