# S6-F10 — verification

**Claim, restated in one line:** `gatekeeper.md` offers steps "to remove everything the app has
added" and lists three places on disk, but an engine install leaves pip's default cache
(`~/Library/Caches/pip`) and the app's `UserDefaults` write leaves
`~/Library/Preferences/io.github.jasonrandazza.ohyesmlx.plist`, neither of which the doc names.

## What the code does (line numbers verified in this worktree)

**The pip argv carries no `--no-cache-dir`.**

- `ohyesmlx/engines.py:813-828` — the one pip argv: `python -I -m pip install --isolated
  --no-input --disable-pip-version-check --require-hashes --only-binary :all: --no-deps -r
  <constraints>`. Both pip engines (`mlxlm`, `optiq`) are built by this same `_command_plan`
  (`ohyesmlx/engines.py:779`).
- `grep -n "no-cache" ohyesmlx/engines.py` → no match. The flag appears nowhere in the package.
- Consequence: pip writes its wheel cache at its default location, `~/Library/Caches/pip`
  (pip's documented behaviour for this platform; not observed on the test account — that is the
  finding's own stated limit, and it is honest). The closure is 105 pinned packages
  (`docs/threat-model.md` P5-12 evidence, 105 hashed pins), and the MLX wheel set is large, so
  the cache is a substantial fraction of the install's download size. The hash-checked wheels
  are fetched once per install anyway; the cache buys a re-install nothing the hashes have not
  already pinned.

**The `UserDefaults` write leaves a preferences plist.**

- `app/Sources/OhYesMLXKit/AppModel.swift:213` — `inflightKey = "inflightJob"`; `:776-779`
  `writeInflight` calls `defaults.set([...], forKey: inflightKey)`; `:783` reads it back. The
  stored value is the in-flight job record the app restores after a crash.
- `:221` and `:235` — both initialisers default `defaults: UserDefaults = .standard`. In the
  shipped app the default is used (the production caller passes no `defaults`), so the write
  lands in the app's preferences domain.
- `app/Resources/Info.plist:9-10` — `CFBundleIdentifier` is
  `io.github.jasonrandazza.ohyesmlx`, so the domain is
  `~/Library/Preferences/io.github.jasonrandazza.ohyesmlx.plist`.

**The doc says "three places" and none of the three is either of those.**

- `docs/release/gatekeeper.md:71` — "OhYesMLX keeps three places on disk"; the table at `:75-77`
  lists `~/Library/Application Support/OhYesMLX`, `~/.cache/huggingface/hub`, and
  `~/Library/Caches/OhYesMLX`.
- `:79-87` — the removal steps: quit, delete Application Support/OhYesMLX, delete
  `~/.cache/huggingface/hub`, delete `OhYesMLX.app`. No pip cache, no preferences plist.
- The third row is itself build-machine-only: `scripts/fetch_python_standalone.sh:20-22` puts
  the tarball and unpacked tree under `~/Library/Caches/OhYesMLX/build`, and nothing at runtime
  writes there — the doc says so in the same row ("Only used when building from source").

So a user who runs the steps to reclaim disk keeps the pip cache (the largest of the additions
for a single installed engine) and a small plist.

It asks `install_plan("mlxlm", 15)` and `install_plan("optiq", 15)` for their pip step and

Red-check: with `install_plan` in the test module patched to return a step whose command ends in

was edited.

## What is not verified

- pip's cache location was read from pip's documentation, not observed: no engine was installed
  (the order forbids it), and there is no pip cache path in the repo to point at.
- The size of the cache was not measured. The finding says "hundreds of MB"; the wheel closure
  is 105 packages, but I did not sum the MLX wheel sizes.
- That `UserDefaults.standard` in a sandboxed or non-sandboxed shipped bundle writes exactly
  `~/Library/Preferences/io.github.jasonrandazza.ohyesmlx.plist` was not observed; on modern
  macOS `cfprefsd` writes the domain under that path for a non-app-store bundle, which is the
  standard behaviour relied on here.
- Whether the plist is worth listing is a judgement: it is a few hundred bytes. The pip cache is
  the part of the claim with disk consequences; the plist is the part that makes "everything"
  false.
