# S3-F11 — `HTTPBackend.events` reconnects forever on every error except `unknown_job`

**Claim (one line):** `events` treats only `unknown_job` and cancellation as terminal; any other
error — a refused connection after the backend exits, a 401, a 429 — sleeps `retryDelay` and asks
again, for the life of the process, so `AppModel.start()`'s `for try await` never returns and its
trailing `refreshRecommendations` never runs.

## Reproduction

New file `app/Tests/OhYesMLXKitTests/FableS3F11Tests.swift`, one test. The transport counts every
`lines(for:)` call and throws `URLError(.cannotConnectToHost)`; the retry delay is 2 ms so half a
second is enough to see the loop. The test asks whether the stream *ends* (0.5 s bound) and then
reports how many reconnects happened before it was told to stop.

```
$ cd app && OYMLX_DEV_PYTHON=…/app-dev-venv/bin/python swift test --filter FableS3F11Tests
FableS3F11Tests.swift:52: error: … Asynchronous wait failed: Exceeded timeout of 0.5 seconds,
  with unfulfilled expectations: "the events stream ends after a refused connection".
FableS3F11Tests.swift:59: error: XCTAssertLessThan failed: ("190") is not less than ("30") -
  events reconnected 190 times in half a second to a port nothing is listening on
Test Case '-[OhYesMLXKitTests.FableS3F11Tests testEventsGivesUpOnARefusedPort]' failed (0.576 s).
```

190 attempts in 0.5 s is the 2 ms test delay doing what the 200 ms default does at 5/s. Nothing
in the stream ends on its own.

## Code path, as cited — every line number verified

- `app/Sources/OhYesMLXKit/HTTPBackend.swift:110-162` — `events` is an `AsyncThrowingStream`
  over one `Task` holding a `while !finished` loop.
- `:146-149` — the only two terminal catches: `BackendError` with `code == "unknown_job"`, and
  `CancellationError` (i.e. `Task.isCancelled`).
- `:150-155` — everything else: `if Task.isCancelled { finished = true } else { try? await
  Task.sleep(for: retryDelay) }`. The loop is bounded by nothing but the task being cancelled, and
  the only holder of that task is the stream's own `continuation.onTermination` (`:160`), which
  fires when the *consumer* stops iterating — which it never does.
- `:62` — `retryDelay` defaults to `.milliseconds(200)`: five reconnects a second, as the finding
  says.
- `:28-34` — `URLSessionTransport.lines` turns any non-2xx into a thrown `BackendError`
  (`Self.error(data:status:)` at `:199-208`, code `bad_response` if the body does not parse). A
  `401` or a `429` therefore lands in the generic catch at `:150` unless its code happens to be
  `unknown_job`. Confirmed for 401/429 by reading; not probed against a server.
- Consumer side, `app/Sources/OhYesMLXKit/AppModel.swift:650-660` — `start()` awaits the stream
  with no timeout and no cancellation; `:661-665` is the `refreshRecommendations()` the finding
  says never runs. `:594-598` (`adopt`) wires `running.onExit` to `backendExited`; `:531-539`
  (`backendExited`) sets `backendStopped` and marks the job `.interrupted` and cancels nothing.
  `:386-408` (`relaunch`) builds a new `HTTPBackend` through `adopt` but keeps no handle on the
  old `start()` task, which is still looping against the old port and token.

## What I did not verify

- No live backend: the failure is reproduced with a fake transport, so I have not observed a real
  `URLSession` connection-refused error, only the shape the code produces for one (`URLError`).
- I did not measure the CPU cost of the 5/s loop; it is small, which is consistent with Low.
- Whether the stream also survives `.done`-less EOF is upstream of this finding (S3-F1).
