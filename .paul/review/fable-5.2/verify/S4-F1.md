# S4-F1 — stage B does not re-run the occupied-port / Osaurus-app check

## Claim

Stage B calls `measured(top["engine"], …)` with no `_skip_reason` check, so an engine whose port
became occupied — or an Osaurus app the user opened — between the two stages is driven into a
cell, where stage A would have recorded a SKIPPED cell with its reason.

The literal claim is true. The finding's stated mechanism (the harness's start/stop path and the
stale-instance sweep run against the user's process) is false: `Runtime.start` refuses an
occupied port and a resident Osaurus app before anything is spawned, and no handle exists to
stop. What the missing check actually costs is a wrong cell status — `N/A` with a start-refusal
message instead of `SKIPPED` with "quit X first" — and, on the Osaurus path, a pin/restore cycle
over the user's live settings files before the start is refused. See "Impact" below.

## Impact vs the finding's failure scenario

The finding's stated harm — "the harness's start/stop path and stale-instance sweep run against
the user's process", ending their server — does not occur through this gap. `Runtime.start`
checks `_port_is_free` and `_resident_osaurus_pids` before spawning, so no `Handle` is created
and `_shutdown` (the only path that kills other listeners) never runs against the occupant; the
orphan sweep only touches this harness's own ledger and identity-checks every pid. The gap a
second check would close is smaller:

- Port case: the stage-B cell records `N/A` with `"runtime 'optiq' did not start:
  RuntimeStartError: port <n> is already held by a listener this run did not start; refusing to
  start optiq over it"` (`measure.py:845-851`), where stage A would record `SKIPPED` /
  `"quit optiq first"`. A reporting inconsistency, no user process touched, no number published.
- Osaurus case: `quickbench.measure_cell` runs `recover`/`pin` before `run_cells`, so a live
  app's config files are backed up and rewritten, then the start refuses and `restore` runs
  (verified byte-exact). This violates stage A's stated rule ("skipped with a reason before
  anything of theirs is started", `quickbench.py:524-525`) and can race a running app's own
  settings writes — the drift check would fail the cell if it did.
