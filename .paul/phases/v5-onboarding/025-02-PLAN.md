<objective>
## Goal
`ohyesmlx canary [--engines a,b] [--record]` measures one fixed cell per engine, compares decode tok/s and TTFT to the baseline stored in the manifest, and prints a verdict per engine: `no effect on our tables` (within the noise floor) or `moved N%: re-run <grids>`.

## Purpose
Decision 135. A version bump is cheap to judge (about 10 minutes) instead of silently invalidating or needlessly re-running every table.

## Output
`ohyesmlx/canary.py` (new module, approved), `canary` subcommand in cli.py, baseline fields in the manifest, tests, one live run.
</objective>

<acceptance_criteria>

## AC-1: Verdict logic is pure and literal-tested
Given a baseline (decode 70.0 tok/s, TTFT 0.40 s) and a new measurement
When `canary.verdict(baseline, measured, floor=0.05)` runs
Then decode 68.0 (-2.9%) is "no effect", decode 62.0 (-11.4%) is "moved -11.4%", TTFT 0.50 (+25%) is "moved +25%", and the worst-moved metric names the verdict; boundary exactly 5.0% is "no effect"

## AC-2: Canary composes cells through the one selector
Given the manifest canary fields (format, repo id, workload) per engine
Then `canary` builds a `--cells` string and invokes the existing run path; a test proves no second selection mechanism exists (the string equals what `build_cells` accepts)

## AC-3: A FAIL or incoherent cell is never a verdict
Given a cell that fails the coherence gate or errors
Then the verdict for that engine is `FAIL: <reason>`, never a number comparison

## AC-4: Version recorded, nothing adopted silently
Given a run
Then the verdict line prints baseline version vs measured version (from the engine's real version probe), and the manifest changes ONLY under `--record`, which writes version, verified date and new baseline for the engines passed

## AC-5: Measurement discipline is enforced by the command
Given any canary invocation
Then it prints the quiet-machine rule and refuses to start without `--yes` (confirm-before-measuring), and runs cells one engine at a time in manifest order with the existing stop-previous-then-start discipline

## AC-7: Contention is recorded and gates the baseline <!-- added 2026-10-29, Jason cannot close apps -->
Given any canary run
Then 1-minute load average (os.getloadavg, injected in tests) is read before and after each engine's cell and stored in the verdict; an engine whose load exceeds a named constant (default 4.0 on this 12-core host, one definition in canary.py) is marked `noisy`; `--record` refuses a noisy engine unless `--allow-noisy` is passed, and the verdict line says so

## AC-6: Live run (human checkpoint)
Given Jason's go and a quiet machine
Then one canary run records the first baselines for the five engines at their current installed versions, written up in `docs/research/`
</acceptance_criteria>
