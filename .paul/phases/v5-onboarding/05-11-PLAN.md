## AC-1: Stage B re-checks the engine before each sibling cell (S4-F1)
```gherkin
Given stage A picked a winner and stage B is about to measure a sibling
When, before the sibling's download and again after it, the winner is refused by `_skip_reason` (Osaurus app open, or `port_plan` refuses)
Then no stage-B start happens for that sibling, a SKIPPED cell carries the refusal reason,
  an owned sibling is evicted as usual, and the run continues to the next sibling;
And a refusal found before the download spends no bytes on that sibling  <!-- audit-added -->
```

## AC-2: A stage-B sibling download hears Stop and Stop now, and its progress reaches the caller (S4-F4)
```gherkin
Given stage B is downloading a sibling
When the run's `cancel` or `abort` becomes true
Then the download is passed a cancel callable that returns True, the run ends "cancelled",
  and an owned partial is evicted or named in not_evicted (existing sweep);
And the download's `progress` events are forwarded to the run's emitter (stage "B"), not discarded — at most one per
  whole percent of the sibling, so a slow multi-GB fetch stays far below the job buffer's MAX_EVENTS=10,000 <!-- audit-added -->,
  while its `error` events are still read for the skip reason
```

## AC-3: Stage B never runs a sibling on an engine its catalog row does not list (S4-F8)
```gherkin
Given a sibling whose `engines` does not contain the stage-A winner
When stage B reaches it
Then it is not downloaded and not measured; a SKIPPED cell reads "<format> is not listed for <engine>"
```

## AC-4: An install that fails late, or whose failure path raises, rolls back and ends with `done` (S1-F7, S4-F10)
```gherkin
Given an install whose pip steps succeeded but whose lab-path record refuses (bad lab-paths.json, group-writable bin),
  or whose failure path raises (log append ENOSPC, emitter raising on `error`, Popen raising)
When the install ends
Then the venv this install created is gone, and the stream ends `error` then `done` where the emitter still works;
And the lab-paths file is validated before the first step (a bad file refuses with nothing created);
And the install-log append is best-effort: it can never abort the cleanup path
```

## AC-5: "Installed" for a lab engine means startable from here (S4-F2)
```gherkin
Given mlx-lm or OptiQ is found by detection
When it is reachable neither by a recorded lab path nor by the PATH the start of that engine will use
  (`runtimes._engine_env` — one definition, asked, not copied; the PATH it reads is injectable so a fake
  detection env never consults the real os.environ  <!-- audit-added -->)
Then detection does not report it installed for that process, and `install` does not refuse `already_installed`;
And an unrecorded venv under the app's engines dir (killed mid-install) is removed and reinstalled by `install`
  (only inside `engines_dir`, only the root this engine's plan would create, never a recorded lab path, never a path
  outside it);
And if any live process's argv is inside that root (a pip that survived a hard-killed backend, running in its own
  session), `install` refuses `install_in_progress` and removes nothing  <!-- audit-added -->;
And a global install (`~/.local/bin/optiq`, Homebrew) is left untouched — the app installs its own recorded copy beside it;
And under the CLI, where that global script is on the start PATH, it still reports installed (no CLI behaviour change),
  pinned by a test  <!-- audit-added -->
```

## AC-6: Memory sentences use the factor that decided the row (S4-F6)
```gherkin
Given `_fit` decides with COMFORTABLE_FACTOR (2.0) and TIGHT_FACTOR (1.25)
When a row is excluded for memory
Then its sentence quotes size × TIGHT_FACTOR (the line it missed) against the budget;
When a row is offered
Then "to spare" is budget − size × (the factor of its fit), never budget − size;
And the `_gb` rounding never shows an offered row's need above the budget (test_fable_s4_f6 green, all cases)
```

## AC-7: Results shows the run's own caveats (S3-F9)
```gherkin
Given a finished quickbench summary
When a stage's `load.label` is set ("this Mac was busy")
Then Results shows that line beside the stage caveat;
When `stage_a.tie` names more than one engine
Then no engine is badged "fastest in stage" — each tied engine reads "tied" — and the best card says the result is a tie
  within the noise band rather than naming one engine as best on its own
```

## AC-8: P5-11 — a row with files on disk that do not match is offered "Re-download" (P5-11)

```gherkin
And the Models row reads "Re-download" (never "corrupt") for it, and "Download" for a row with nothing on disk;
And what the Re-download button does is what `fetch.download` actually does with a wrong-size file (read it; if it
  refuses rather than replacing, the copy says so and the action is Remove-then-Download, not a silent failure)
```
