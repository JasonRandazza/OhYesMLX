## AC-1: The interpreter is pinned and verified
```gherkin
Given `scripts/fetch_python_standalone.sh` (the committed record of the download, AGENTS.md download rule)
Then it fetches exactly `cpython-3.14.10+20261026-aarch64-apple-darwin-install_only.tar.gz` from the astral-sh/python-build-standalone release `20261026`, verifies sha256 `30a18bcb9ab75e485b4bf4e5d783dde165571e7e42c56dff47a2d2c5345183a4` before unpacking, and refuses (non-zero, nothing unpacked) on a mismatch
And it caches the tarball under `~/Library/Caches/OhYesMLX/build/` so rebuilds do not re-download
```

## AC-2: The bundle
```gherkin
When `scripts/build_app.sh` runs
Then `dist/OhYesMLX.app` holds Contents/MacOS/OhYesMLX (swift build -c release), Contents/Info.plist (bundle id `io.github.jasonrandazza.ohyesmlx`, CFBundleShortVersionString from `ohyesmlx.__version__` — one definition, LSMinimumSystemVersion 14.0, LSApplicationCategoryType developer-tools), Contents/Resources/python (the verified interpreter) with `ohyesmlx/` copied into its site-packages and precompiled with that interpreter's `compileall`
And the bundle is signed ad hoc inside-out (every Mach-O under Resources/python, then the app) and `codesign --verify --deep --strict dist/OhYesMLX.app` passes
And `dist/OhYesMLX-<version>.zip` is made with `ditto -c -k --keepParent`
And the launcher's argv becomes `[python, "-I", "-B", "-m", "ohyesmlx.cli", "app"]` (never write bytecode into the bundle; P5-6), with LauncherTests and v5-app.md updated in the same change
```

## AC-3: The SBOM (P5-12)
```gherkin
Then `scripts/make_sbom.py` writes `dist/OhYesMLX-<version>-sbom.json`: the interpreter (name, version, release tag, url, sha256), ohyesmlx (version, git commit, source sha256 from `measure._source_sha256()` — ask that function, do not copy it), the Swift toolchain version that built the binary <!-- audit-added -->, and every pinned engine dependency from `ohyesmlx/constraints/*.txt` (engine, package, version, every sha256)
And it is stdlib only and has one runnable check
```

## AC-4: The packaging rules hold on the bundled interpreter
```gherkin
When `scripts/check_bundle.sh dist/OhYesMLX.app` runs
Then P5-3: the bundled python under `-I` has no user site, no cwd and no PYTHON* effect on sys.path (print and assert)
And P5-4: under `env -i HOME=... PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `-I` HTTPS GET of https://huggingface.co/api/models/mlx-community/Qwen3-0.6B-4bit returns 200 with verification on
And P5-6: the app copied onto a read-only disk image (`hdiutil create -srcfolder ... -format UDRO`, mounted), launched from there with `open`, reaches a served `GET /hardware` (via the backend's stderr/launch, or a process check), is quit, and `codesign --verify --deep --strict` on the mounted copy still passes
And P5-9: the backend process's environment PATH (`ps eww`) is launchd's default
And each check prints PASS/FAIL and the script exits non-zero on any FAIL
```

## AC-5: Gatekeeper and first run
```gherkin
Then `docs/release/gatekeeper.md` explains, for a user with no terminal: the zip is not notarized (no Developer account, D7); first open is refused; the way past on current macOS (System Settings > Privacy & Security > Open Anyway, after one attempt) and why it is safe to check the SBOM and the zip's sha256 published beside it; what the app writes and where (Application Support, the HF cache), and how to remove it all

```

## AC-7: A translocated or moved app does not strand its engines <!-- audit-added: must-have -->
```gherkin
Given engine venvs are created from `sys.executable`, i.e. a path inside the .app
When the app is opened from Downloads with the quarantine flag, macOS App Translocation runs it from a random read-only path that changes per launch, so any venv made in that run points at an interpreter that is gone next launch
Then the app detects translocation (its bundle path contains `/AppTranslocation/`, or `SecTranslocateIsTranslocatedURL` says so) before spawning the backend and shows a full-window state: "Move OhYesMLX to your Applications folder, then open it again" with a Quit button; no job can start (AppModel test with an injected bundle path)
And gatekeeper.md says to move the app to Applications before the first open, and that moving it later means reinstalling the pip engines (mlx-lm, OptiQ)
And the PBS license files in the tarball are shipped unmodified inside Contents/Resources/python (no stripping) <!-- audit-added: strongly-recommended -->
```
