## AC-1: One formatter, tested
```gherkin
Given `Format` in OhYesMLXKit
Then memory uses binary units labelled GB as macOS does (68719476736 -> "64 GB"), disk and download sizes use decimal GB/MB with one decimal (43377606656 -> "43.4 GB", 351386061 -> "351 MB"), rates "62.1 tok/s", durations "0.21 s" / "about 11 min"
And number and unit are joined by one non-breaking space, so they never split across lines
And every view that shows a byte count, rate or duration calls `Format` (grep: no `ByteCountFormatter`/`String(format:` outside Format.swift)
And `AppModel.formatGB` is deleted and its callers use `Format` (one definition) <!-- audit-added: must-have -->
```

## AC-2: The shell
```gherkin
Given a supported Mac and the backend up
Then the window is a NavigationSplitView: sidebar section "Setup" with the five steps (SF Symbols as comped), the current step selected, completed steps showing a trailing checkmark.circle in .secondary (Your Mac: hardware loaded; Engines: at least one engine installed; Models: a pick downloaded; Benchmark: a finished quickbench; Results: never), and a footer "Nothing changes on this Mac without a click."
And the detail toolbar shows the screen title, the subtitle "Step N of 5", and that screen's trailing actions
And the default window size is 1100x720 with a minimum of 900x600
And launching / couldntStart / unsupported / backend stopped are full-window states with no sidebar: centred SF Symbol, title, body, one prominent action (Try Again / Quit OhYesMLX / Relaunch) and, for couldntStart and backend stopped, the stderr tail in SF Mono with a Copy Details button
And unsupported shows `unsupported_reason` and no control leads past it (Q6)
And while a job runs, the sidebar stays navigable (navigation is not a job)
And `applicationDidFinishLaunching` sets `NSApp.setActivationPolicy(.regular)` and activates, so the unbundled `swift run` binary is a normal foreground app with a Dock icon and a working Cmd-Q (found in 05-02 verification: it ran background-only) <!-- audit-added: strongly-recommended -->
And the window enforces its minimum size (`.windowResizability(.contentMinSize)` with a 900x600 minimum frame) <!-- audit-added -->
```

## AC-3: The interrupted banner (Q2)
```gherkin
Given `interruptedJob` is set
Then a one-line bar above the detail content reads "<Kind> of <name> was interrupted when OhYesMLX quit." with Retry and Dismiss, on every screen, and never retries by itself
```

## AC-4: Your Mac (with Welcome)
```gherkin
Then it shows the welcome sentence (DESIGN.md §1 voice), and a grouped Form: Chip, Processor ("12 CPU cores, 30 GPU cores"; GPU omitted when null), Memory ("64 GB unified"), Free disk, macOS, and "About 46 GB is available for model weights" with an `estimated` badge (model_budget_bytes, binary GB)
And Scan Again re-requests hardware; Continue to Engines moves on
```

## AC-5: Engines
```gherkin
Then each engine is one row: title, version in .monospacedDigit, blurb, and a trailing state: glyph + "Installed, tested" / "Installed, untested" (untested build badge) / Install… button
And Install… opens the consent sheet listing `install.steps` (label; command in SF Mono when present), the estimated size, "Needs admin password: Yes/No", and for guided_download "Opens the official download page, then checks again"; NO uninstall/undo row (DESIGN.md §4.1); Install is the default button, Cancel the escape
And while a job runs, every Install… is disabled with the busy reason beside it and as its accessibility hint (Q1)
And a running install shows its progress (fraction or indeterminate) and last message in that row; a failed install shows the failure code and the output tail in SF Mono, with Try Again
And Check Again in the toolbar, app activation and the screen appearing all re-request engines (Q5)
```

## AC-6: Screenshots of every state, without a live job
```gherkin
Given a DEBUG build started with `OYMLX_STUB_SCENARIO=<name>`
Then the app runs on StubBackend in that scenario (no backend spawned) — scenarios at least: welcome, engines, engines-consent, engines-busy, engines-failed, couldnt-start, unsupported, backend-stopped, interrupted
And in a release build the variable is ignored (#if DEBUG)
```
