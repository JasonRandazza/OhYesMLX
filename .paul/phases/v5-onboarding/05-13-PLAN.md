<acceptance_criteria>

## AC-1: Sealed bundle (F1, F2)
```gherkin
Given a build
Then the interpreter tree is unpacked from the sha256-verified tarball into a fresh temp dir every build and deleted after
And the build runs with -B, compileall runs with -f in unchecked-hash mode
And a walk fails the build on any pyc whose flags are not unchecked-hash, or on any .py with no pyc
```

## AC-2: check_bundle can fail for P5-6 (F3)
```gherkin
Given check_bundle.sh
Then besides the read-only run, it copies the bundle to a writable temp dir (mtimes not preserved)
And it runs the bundled python with `-I -m venv <tmp>` and `-I -c "import email, json, tempfile, ssl"` (no -B)
And it verifies the signature and asserts no file under the copy is newer than the copy itself
```

## AC-3: P5-9 and P5-4 report honestly (F7, F11)
```gherkin
Then an unreadable environment prints `SKIP P5-9 (...pinned by LauncherTests...)`, which is not counted as a failure
And PATH is matched as a whole token, with PYTHON[A-Z]*= tested
And the threat-model evidence cell cites what actually established P5-9
And P5-4 checks the CA paths before any network call, and tells "(certificate)" from "(network unreachable; rerun)"
```

## AC-4: SBOM and sha256 (F6, F8)
```gherkin
Given a dirty `ohyesmlx`/`app` tree
Then the build refuses, or writes git_dirty: true and no commit
And the source digest is computed by the bundled interpreter (-I -B) over what shipped, with data files in a second digest
And the build writes OhYesMLX-<v>.zip.sha256 and prints it
And gatekeeper.md says the ad-hoc signature only lets macOS run the code, while the sha256 shows the download is unaltered
```

## AC-5: Moved-app repair and clean uninstall (F4, F10)
```gherkin
Given an app-managed venv whose bin/python no longer resolves to an existing executable
Then detection reports the engine not installed, and install removes the venv and reinstalls
  (this reuses 05-11's unfinished-root path, including its install_in_progress check)
And every pip argv carries --no-cache-dir
And gatekeeper.md's removal table and steps include the Preferences plist
```

## AC-6: The smoke runs the bundle (F5); the quarantine path is scripted (F9)
```gherkin
Then the smoke client takes --python <path> and spawns [python, -I, -B, -m, ohyesmlx.cli, app] under the launcher's environment
And the driver copies dist/OhYesMLX.app into the test account, passes its interpreter, and records which artifact ran
And gatekeeper.md (or a release checklist in it) carries the quarantined-zip step: the xattr, the unzip, the
  move screen, approval, and a served /hardware
```
The quarantined-zip step and the clean-account smoke are run later by Jason. They are not part of this plan's gate.

## AC-7: Gates
```gherkin
Then all 10 red-test files pass (each correction minimal and listed), the full pytest suite and swift test are green
And the coordinator rebuilds dist/ with scripts/build_app.sh, and check_bundle.sh shows all PASS (or SKIP per AC-3)
```
