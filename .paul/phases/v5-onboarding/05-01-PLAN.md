<objective>
## Goal
`POST /jobs/{id}/cancel` with body `{"now": true}` stops a running quickbench mid-cell: the in-flight engine is
stopped at once, the cell is recorded `ABORTED` with no number, and the run ends `cancelled` through the same
stop, eviction and Osaurus-restore path a between-cell cancel already takes. A bodyless cancel is unchanged.

## Purpose
Jason's answer to prototype Q3 (2026-11-13): offer both "Stop after this cell" and "Stop now". The backend could
only stop between cells. The shape is pinned in `docs/interfaces/v5-app.md` ("Backend addition"); that section
is the spec, and this plan does not restate it.

## Output
The cancel body and its refusals in `server.py`; `runtimes.stop_own_engines`; quickbench's `abort` probe and the
`ABORTED` status; tests at each seam; the two interface docs updated to point at v5-app.md.
</objective>

## AC-1: The cancel body is validated, and a bodyless cancel is unchanged
```gherkin
Given a running job
When `POST /jobs/{id}/cancel` arrives with no body, or with `{}`
Then it behaves exactly as today (202, cancel flag set, abort flag not set, `stop_engines` not called)
When the body is `{"now": true}` and the job is a quickbench
Then the cancel and abort flags are both set, `stop_engines` is called once, and the answer is 202 `{"job_id"}`
When the body has another key, or `now` is not JSON true
Then 400 bad_args naming the key, and no flag is set
When `now` is sent for an install or download job
Then 409 not_abortable, and no flag is set
And unknown_job (404), not_cancellable (evict, 409) and job_finished (409) are still answered before the body matters
And a non-JSON Content-Type, an oversize or missing-length body with a non-empty body, and invalid JSON get the same 415/413/400 codes `POST /jobs` gives
```

## AC-2: `runtimes.stop_own_engines` stops only this process's engines
```gherkin
Given a ledger directory holding this process's file with two entries and another live owner's file with one
When `stop_own_engines(root)` runs (with `_shutdown` injected or monkeypatched)
Then `_shutdown(pid, port, tuple(stop_command))` is called for this process's two entries only, and it returns 2
And the ledger files are byte-identical afterwards (it never writes)
And a `RuntimeStopError` from the first entry writes one stderr line `{"error": {"code": "abort_stop_failed", "message": ...}}` and the second entry is still stopped
And an absent or unreadable ledger file returns 0
```

## AC-3: quickbench records an aborted cell as ABORTED and ends cancelled
```gherkin
Given `quickbench.run` with fake run loop, an `abort` probe that turns True while stage A's first cell is measured, and the existing fakes
When that cell's `measure_cell` returns (a FAIL row, as an engine stopped mid-request produces)
Then the cell's record has status "ABORTED", reason "stopped by the user mid-cell; no number is reported", and no figures
And no further cell is measured, `summary["ended"] == "cancelled"`, `best` is null, the stream ends with the module's cancelled `error`/`done`
And the Osaurus restore and sibling eviction run exactly as for a between-cell cancel (assert with the existing fakes)
And the same holds when the abort lands during a stage B cell
And an ABORTED cell is never the winner (`_winner` ignores it as it ignores FAIL)
And with the default `abort` (never) every existing quickbench test passes unmodified
```

## AC-4: The server wires the probe and the stop
```gherkin
Given the server's quickbench call in `_run_job`
Then it passes `abort=job.aborted` alongside `cancel=job.cancelled`
And `stop_engines` is an injectable attribute on the server object, defaulting to `runtimes.stop_own_engines`, the way `install`/`download`/`quickbench` already are
And a test with a fake quickbench that blocks until abort, plus a fake `stop_engines`, shows: POST cancel {"now": true} -> stop_engines called -> the fake sees abort() True -> the job ends
```

## AC-7: Stop now is safe against its own races <!-- audit-added: must-have -->
```gherkin
Given a "Stop now" that stops the engine while the cell's own `handle.stop()` (measure.py's finally) is about to run
When that second stop raises (`RuntimeStopError`) or `measure_cell` raises for any reason while `abort()` is True
Then the cell is still recorded ABORTED, the run still ends "cancelled" (never "error"), and the Osaurus restore and sibling eviction still run (test: a fake measure_cell that raises RuntimeStopError after abort is set)
And `stop_engines` runs on a daemon thread the handler starts after setting both flags, so the 202 answers at once and is never held for the TERM/KILL grace (test: a fake stop_engines that blocks on an Event; the 202 arrives before it is released)
And a second `{"now": true}` on the same job answers 202 without starting a second stop (one stop per job; test counts calls)
And an abort that arrives after the last cell's engine stopped stops nothing and the run's ending is unchanged
```

## AC-6: A low_disk refusal carries its numbers
```gherkin
Given a download or install refused for disk (`fetch.py` ~823 and ~1148, `engines.py` ~1329)
Then the `error` event's payload is `{"code": "low_disk", "free_bytes": int, "needed_bytes": int}` (the same two
 numbers the message already prints), so the app can say how much to free without parsing English or
 restating the disk-margin rule (prototype Q4)
And the message text is unchanged
```

And neither file restates the mechanism
