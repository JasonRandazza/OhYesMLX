## AC-1: One sweep, by process, not by port (item 5)
```gherkin
Given scripts/sweep.sh is sourced (it needs $PY)
When sweep runs
Then every process `runtimes.resident_engines()` reports is killed (SIGKILL, as today) and awaited, then a
  `sleep 3` settles as today
And nothing that is not an engine is signalled. A non-engine listener on 8000/8080/8081/8100/1337 survives a sweep
And `osaurus mcp` is never signalled (`_engine_of` does not match it)
And when `resident_engines` raises (ps unreadable), sweep prints the error and returns non-zero rather than
  claiming the machine is clear
And the kill loop is one Python function in runtimes.py, called by sweep.sh with `$PY -c`, and tested with
  `resident_engines` and the signal function monkeypatched. No real process is killed by a test
And no script under scripts/ defines its own `sweep()` any more. Each one that had one sources sweep.sh
  (a test asserts that)
And sweep never calls `exit`: it only returns its status, because osaurus-pin.sh's signal trap runs
  `sweep; osaurus_restore` and an exit there would skip the Osaurus restore <!-- audit-added -->
And every sweep call outside a trap becomes `sweep || exit 1`, so a run whose machine cannot be confirmed clear
  never starts or continues a column (one model resident is a hard rule). The EXIT trap still restores Osaurus <!-- audit-added -->
And a pid that has gone, or that this user cannot signal, is reported in a line, not raised. An engine still
  alive after SIGKILL and the await makes the function fail (non-zero) <!-- audit-added -->
And sweep.sh refuses loudly when $PY is unset (`: "${PY:?sweep.sh needs PY}"`) <!-- audit-added -->
```
