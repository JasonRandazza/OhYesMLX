## 1. Executive Verdict

The plan is conditionally acceptable. The docs half (items 1 and 10) is well bounded: notes go beside figures, with no edits, and every number is copied from the audit. The scripts half had one real hazard. The plan said what the sweep does on failure, but not what the caller does. A sweep that fails quietly lets a run start with a second model resident, which AGENTS.md calls void. A sweep that `exit`s inside the Osaurus signal trap would skip the byte-exact restore of Jason's settings.

## 2. What Is Solid

- **The kill decision moves to `_engine_of`,** the one engine definition. It already excludes `osaurus mcp` and non-engine listeners.
- **The kill loop is Python and tested;** the shell only calls it.
- **Pin copies are converted only on an exact match,** with differences named, not forced.
- **Item 10 never edits a figure.**

## 3. Enterprise Gaps Identified

1. **Caller semantics on sweep failure were unstated.** Today's sweeps cannot fail; the new one can, when `ps` cannot be read.
2. **An `exit` inside sweep, reached from the osaurus-pin.sh trap (`sweep; osaurus_restore; exit 130`), would skip the restore.**
3. **Two process cases were unspecified.** One is a pid that has gone, or belongs to another user (`EPERM`), between the scan and the signal. The other is an engine that survives SIGKILL.
4. **An unset `$PY` would make the sweep a silent no-op**, because `$PY -c` with an empty variable fails confusingly.
