## AC-1: Every quickbench ending carries its summary
```gherkin
Given a quickbench run that ends cancelled, restore_failed or error (as well as finished)
Then the stream carries one `result` event whose payload is the summary just written, before the ending's `error`/`done`
And the finished path is unchanged; `best` stays null on every non-finished ending
And v5-quickbench.md says so in one sentence
```

## AC-2: The summary is typed
```gherkin
Given fixtures quickbench_summary_finished.json and quickbench_summary_cancelled.json (written from the pinned shape; the cancelled one has an ABORTED cell and one not_evicted repo)
Then `QuickSummary` decodes both (cells with optional decode_tps/ttft_s, stage caveats, best optional, not_evicted) and AppModel exposes it typed instead of `JSONValue`
And AppModel also keeps the payload's raw JSON bytes exactly as received, which is what Export writes (a re-encode of the typed value would drop keys the client does not model) <!-- audit-added: must-have -->
```

## AC-3: Models
```gherkin
Then picks render as comp 5's rows with DESIGN.md §4.4 fixes: Start here badge, title, format, fit glyph + word + `estimated` badge, the backend's reason line, one trailing action (Download / Downloaded ✓ with Remove… / Cancel while downloading)
And a pick with `measured_here` shows its quick figure with the `quick: measured on this Mac` badge
And excluded rows are listed under a disclosure "Not recommended for this Mac" with each reason
And the toolbar carries a disk meter: free disk (decimal GB) as a linear gauge
And a download shows fraction and "bytes_done of bytes_total" from the progress payload, with Cancel
And a low_disk refusal shows inline under that row, orange triangle, "Not enough free disk: free <amountToFree> more and try again" (Q4), and the meter refreshes
And Remove… (evict) asks for confirmation in a sheet naming the size it frees
And every Download/Remove is disabled with the busy reason while a job runs (Q1)
```

## AC-4: Benchmark
```gherkin
Given the Benchmark screen
Then the model is chosen there from the downloaded picks (a Picker; default the first Start-here pick that is downloaded); with none downloaded it says "Download a model first" with a button to Models <!-- audit-added: strongly-recommended -->
Given a chosen downloaded pick
Then the plan (from GET /quickbench/plan) shows before anything runs: stage A engines with versions and untested-build badges, stage B formats with "already on disk" or "one extra download, <size>", time estimate (estimated), downloads total, free disk after (estimated), the Osaurus pin toggle with its explanation (default off; sends osaurus true/false), and Start Benchmark (D4)
And a plan refusal (e.g. not downloaded) shows the backend's message with a button to Models
And while running: stage, current cell, overall progress, per-cell results as they land, and two toolbar buttons Stop After This Cell / Stop Now with the one-line explainer; after either press both disable and the state reads "Stopping after this cell…" / "Stopping…" (Q3)
And on any ending the app moves to Results
```

## AC-5: Results
```gherkin
Given a QuickSummary
Then the header card shows best engine + format and decode tok/s with the `quick: measured on this Mac` badge — only when `best` is non-null; a cancelled run shows "This run was stopped; nothing is recommended from it."
And stage A and stage B tables: engine (version), status glyph + word (PASS / FAIL / SKIPPED / Stopped by you for ABORTED), decode tok/s, TTFT, note (reason), each followed by its caveat sentence
And one plain line per not_evicted repo: "Left on disk: <title> (<size>) — it was in use. You can remove it from Models." (Q7; title and size from recommendations, repo id if unknown)
And Export Results… opens NSSavePanel and writes the summary JSON exactly as received (D8)
And dark mode passes contrast by construction: semantic styles only (DESIGN.md §4.2)
And with no run in this launch, Results says "No benchmark has run since OhYesMLX opened." and lists any picks whose `measured_here` is set, with their quick figure and badge (the backend keeps finished results; the app reads no file) <!-- audit-added: strongly-recommended -->
```
