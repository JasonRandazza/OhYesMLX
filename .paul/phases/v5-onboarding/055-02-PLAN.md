## Goal
Close Phase 5.5 items 2, 3 and 8 (ROADMAP "Phase 5.5"):
- **2:** Retry on an interrupted evict opens Models with the remove-confirm sheet already showing for that model.
- **3:** when a second launch finds the app already running, it activates the *other* instance, never itself.
- **8:** wherever "Free disk" appears, the label names the volume when the Hugging Face cache is not on `/`.

## Purpose
Each item is a small UI defect a user meets:
- **2:** after Retry, the user has to find the model again and press Remove a second time.
- **3:** the second launch may bring itself to the front and then quit, so the first window never comes forward.
- **8:** the figure is the cache volume's free space, but the label reads as if it were the startup disk's.

## Output
The Swift edits, one Python field, the interface docs, new tests, light and dark screenshots, and `055-02-SUMMARY.md`.

## AC-1: Retry of an interrupted evict opens the confirm sheet (item 2)
```gherkin
Given an interrupted job of kind evict for repo R
When retryInterrupted() runs
Then the screen is Models and AppModel publishes an evict request naming R (one optional property, `evictRequest`,
  mirroring `consentRequest`)
And ModelsView, on that request (onChange and on appear), clears it and opens EvictSheet for the pick whose
  modelID is R. It uses the same Pick source and the same `evicting` state that the row's Remove button uses, so the
  sheet and its confirm action are identical to pressing Remove
And when no pick matches R (the model is no longer on disk), the request is cleared and no sheet opens
And nothing is evicted until the user confirms. Retry never starts an evict job by itself (S3-F15 still holds)
And when an evict job is already active (other job controls are greyed, Decision 2026-11-13 Q1), the request opens no
  sheet: it uses the same gate the Remove button uses, so the sheet never offers a confirm the button would refuse <!-- audit-added -->
```

## AC-2: Already-running activates the other instance (item 3)
```gherkin
Given two running apps share this bundle id
When the second launch reports alreadyRunning
Then the instance activated is the one whose processIdentifier is not this process's, and then this one terminates
And when no other instance is found (it quit in between), nothing is activated and this one still terminates
And "the other instance" has one definition in BackendLauncher. `anotherInstanceIsRunning` and the activation both
  use it, with the selection testable on plain pids (no NSRunningApplication is needed in a test)
```

## AC-3: Free disk names its volume (item 8)
```gherkin
Given scan() runs
Then Hardware carries `disk_volume`: the mount point of the volume that `disk_free_bytes` measures. It is derived
  from the same probe path `disk_bytes_at` uses (the nearest existing ancestor, realpath), walking up to the first
  `os.path.ismount` directory. That probe derivation exists once
And on the Swift side `disk_volume` decodes as optional. When it is absent, or is "/", it means the startup disk
And when the volume is "/", every label reads exactly as today: "Free disk", "Free disk after", and the meter's
  accessibility text
And when it is another volume, e.g. "/Volumes/Storage", the labels read "Free disk on Storage" and
  "Free disk on Storage after" (shortened if the layout needs it), and the accessibility label names the volume
And the label text is defined once, as a computed property on Hardware, and every screen asks it
And both interface docs state the field
And when the disk probe fails (scan's `except OSError` path, where free = total = 0), `disk_volume` is null, never a
  guessed "/"; the app then shows the plain "Free disk" <!-- audit-added -->
And Python `Hardware.disk_volume` is the LAST field, `str | None = None`, so the four test constructors of Hardware
  need no edit; Swift's `Hardware.init` gains `diskVolume: String? = nil` LAST for the same reason <!-- audit-added -->
And "Free disk after" (BenchmarkView) takes the label too, because `Plan.free_after_bytes` is measured on the same
  cache volume (`quickbench.py:309`, `free_bytes_at(cache)`) <!-- audit-added -->
```
