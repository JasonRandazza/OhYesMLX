<objective>
## Goal
`ohyesmlx app` starts a stdlib HTTP server on 127.0.0.1 that answers `GET /hardware`, `GET /engines` and
`GET /recommendations` with the pinned JSON shapes, and refuses every request that lacks the per-launch
token, carries a browser `Origin`, or names a foreign `Host`.

## Purpose
Seam S6, tickets T4.1 and T4.2. The SwiftUI app (Phase 5) is a client of this server and nothing else, so
the server is the contract. It is also the riskiest surface v5.0 adds: any web page the user opens can send
requests to 127.0.0.1, and Phase 4's later plans put install and download behind this same server.
The guard lands here, before any endpoint that changes the machine exists (Jason, 2026-11-02: token +
Host + Origin, and a dedicated security-hardening phase after Phase 4).

## Output
`ohyesmlx/server.py` (approved surface), the `app` subcommand (approved surface), `tests/test_server.py`
against a real server on an ephemeral port, the pinned startup line and guard in `docs/interfaces.md`.
</objective>

<acceptance_criteria>

## AC-1: Starts on loopback and announces itself once
```gherkin
Given `ohyesmlx app` (default `--port 0`)
When it starts
Then it binds 127.0.0.1 only (never 0.0.0.0 or ::), on an ephemeral port unless `--port N` is given,
 and writes exactly one line to stdout before serving: {"port": int, "token": str}
And the token is `secrets.token_urlsafe(32)`, fresh per launch, never written to disk or to any log
```

## AC-2: The guard runs before routing, on every request
```gherkin
Given a running server
When a request arrives
Then it is refused in this order, each with the pinned error shape `{"error": {"code", "message"}}`:
 a `Host` other than `127.0.0.1:<port>` or `localhost:<port>` -> 403 `bad_host` (DNS rebinding);
 any `Origin` header at all -> 403 `origin_refused` (a browser page; the app never sends one);
 a missing or wrong `Authorization: Bearer <token>` -> 401 `unauthorized`, compared with `hmac.compare_digest`
And a refused request reaches no handler and runs no scan
And no response ever carries an `Access-Control-Allow-*` header, including to `OPTIONS` (405)
```

## AC-3: GET /hardware
```gherkin
Given an authorised request
When `GET /hardware`
Then 200 with the pinned `Hardware` object from `hardware.scan()`, byte counts as JSON integers
```

## AC-4: GET /engines composes install plans
```gherkin
Given an authorised request
When `GET /engines`
Then 200 with a list of the pinned `EngineStatus` objects from `detect_all()`, where `install` is
 `install_plan(name, macos_major)` for an engine that is not installed and null for one that is
 (`macos_major` is the integer before the first "." of `Hardware.macos`)
And a `ValueError` from `install_plan` is 500 `install_plan_failed` naming the engine, never a silent null
```

## AC-5: GET /recommendations is the pinned composition
```gherkin
Given an authorised request
When `GET /recommendations`
Then 200 with {"picks": [Pick], "excluded": [{"model_id", "reason"}], "unsupported_reason": str|null},
 composed from `catalog.load()`, `hardware.scan()`, `detect_all()` and `Hardware.disk_free_bytes`
And on an unsupported Mac `picks` and `excluded` are empty and `unsupported_reason` is `Hardware.unsupported_reason`
```

## AC-6: Everything else is refused in the pinned shape
```gherkin
Given an authorised request
When the path is unknown -> 404 `not_found`; the method is not GET on these three paths -> 405 `method_not_allowed`;
 a module raises -> 500 `internal` with the exception's message and no traceback in the body
Then every response is `application/json; charset=utf-8`
```

## AC-7: The server dies with its parent
```gherkin
Given the server was started with a pipe on stdin (how the Swift app spawns it)
When stdin reaches EOF, or SIGINT/SIGTERM arrives
Then the server shuts down, releases its port and exits 0
```
