## Purpose
The app's promise on the Models and Benchmark screens is "we fetch what you agree to, we take back only what we
fetched, and the free-disk figure is true". Today a network blip escapes the retry loop (S1-F3) or deletes gigabytes of
valid partial (S1-F4); the disk guard asks `/` while the bytes land on the cache's volume (S4-F3); the free-disk figure
is never re-read after a job (S3-F10); quick-bench can delete a user's own partial (S4-F11), leave its own partial
unreported (S4-F9, S4-F12), and measure a blob of the right size and wrong bytes (S4-F14).

## Output
Fixes in `ohyesmlx/{fetch,hardware,recommend,server,quickbench}.py` and the app (`AppModel`, `Models`, `BenchmarkView`,
stub); 9 Fable pytest files + 1 Swift test copied and green; `docs/interfaces/v5-app.md` (the plan's new
`free_after_bytes`; `disk_free_bytes` now means the cache volume); `05-10-SUMMARY.md`.

## AC-1: A mid-body network error is retried and its partial ledgered (S1-F3)
```gherkin
Given a 200/206 response whose read() yields bytes then raises TimeoutError, ConnectionResetError, ssl.SSLError or
  http.client.HTTPException
When download runs
Then the error enters the same backoff branch as a short transfer (no exception escapes download), and if the
  attempts run out the call returns False with an `http_error` or `size_mismatch` refusal and the partial kept
And any `.incomplete` left behind is on the ledger whether _fetch_file returned or raised (bookkeeping in a finally)
And only `response.read` is inside the catch: an OSError from writing the partial (ENOSPC, EIO) is never retried as a
  network error <!-- audit-added -->
```

## AC-2: Retry exhaustion keeps a valid prefix (S1-F4)

## AC-6: A partial row is judged on the bytes still to fetch (S4-F7)
```gherkin
Given a catalog row 80% present in the cache and free disk ≥ disk_needed(remaining) but < disk_needed(full size)

Then the row is offered, not excluded
And the remainder comes from one definition shared with fetch's own guard: `fetch.missing_bytes(model, cache_dir,
  present=None)`, extracted from `_download`'s `remaining()`. It is **stat-only** (a blob counts as present when it is
  a regular file of the pinned size; else size − `.incomplete` length) so `GET /recommendations` and
  `GET /quickbench/plan` never hash. `_download` passes its own verified `present` map, so the guard's answer is
  unchanged. quickbench.plan's `download_bytes` uses it too (a partial sibling now counts only its remainder)
  <!-- audit-added: the original wording pointed at a computation that hashes -->
And a row with nothing on disk is still excluded on its full size (the S4-F7 control stays green)
```
