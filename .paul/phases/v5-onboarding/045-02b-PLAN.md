<objective>
## Goal
Fix the six remaining findings approved at the 045-01 triage (Jason, 2026-11-03), each test-first:

- T-01 (medium): pip installs are pinned by version, not by hash.
- T-06 (medium): `evict` takes no lock, so it can race a download over the fetch ledger.
- T-07 (low): the installer's interpreter and pip read the user's environment and config.
- T-12 (low): `lab-paths.json` values become the front of PATH after a non-empty-string check only.
- T-13 (low): `evict` trusts any ledger path under the whole cache root.
- T-16 (low): the snapshot-conflict check runs after a multi-GB transfer instead of before it.

T-01 and T-06 detail moves from `045-01-findings-private.md` into `docs/threat-model.md` §7.4 in the commit that
fixes each. After both land, the private file is empty and the 045-01 review logs can be published.

## Purpose
The installers and fetch half of plan 045-02 (Jason's split, 2026-11-03). Phase 5 hands this backend to users who
never open a terminal; what it installs must be exactly the bytes that were measured, and what it deletes must be
exactly what it created.

## Output
Code and tests for the six findings; hashed requirement files for both pip engines and the stdlib script that
produces them; `docs/interfaces.md` and `docs/runtimes/lab-copies.md` updated for every changed contract;

## AC-1: pip installs only hash-verified files (T-01)
```gherkin
Given each `ohyesmlx/constraints/<engine>-<version>.txt` is a full requirements file: every non-comment line is
 `name==version` followed by one or more `--hash=sha256:<64 hex>`, and the engine's own package is one of them,
 pinned to `TESTED_VERSIONS[engine]`
And the hashes are every file PyPI lists for that exact version (`https://pypi.org/pypi/<name>/<version>/json`,
 `urls[].digests.sha256`), produced by `scripts/hash_freeze.py`, a stdlib script that rewrites a freeze in place,
 keeps its header and adds one line naming the date and the source; it exits non-zero naming any pin PyPI has no
 file for, and prints (does not fail on) a yanked pin
When `install_plan` builds a pip engine's install step
Then its argv is `<venv>/bin/python -I -m pip install --isolated --no-input --disable-pip-version-check
 --require-hashes --only-binary :all: -r <constraints_path(engine)>` (no separate `pkg==ver` token; the file
 names it). `--only-binary :all:` is required because hash-checking mode does not cover the PEP 517 build
 dependencies pip fetches to build an sdist, and building an sdist runs its code <!-- audit-added: must-have -->
And a file in which any requirement line has no hash is refused exactly as a missing file is (`ValueError`,
 refused by `install` as `no_constraints`), with a message saying the file carries no hashes
And the same check refuses any line that is not a comment, blank, `name==version`, or a `--hash=sha256:<64 hex>`
 continuation: a requirements file can carry `--index-url`, `--extra-index-url`, `--trusted-host`, `-f`, `-r`,
 `-c` or `-e`, and none of them may appear <!-- audit-added: strongly-recommended -->
And `hash_freeze.py` prints, and the coordinator reviews in the SUMMARY, every file uploaded more than 7 days after
 the earliest file of its version (`upload_time_iso_8601`): a file added to an existing version is exactly T-01's
 attack, and one added before the freeze would otherwise be trusted blindly. Late files are reported, not dropped,
 because a new-ABI wheel (cp314) is often uploaded late for good reasons <!-- audit-added: must-have -->
And `hash_freeze.py` fetches only over `https://pypi.org` with the default SSL context, writes nothing unless every
 pin resolved (one `atomic_write_text` at the end, so a failure leaves the file byte-identical), takes its fetcher
 as a parameter, and has `tests/test_hash_freeze.py` (no network): hashes written, pin pairs preserved, a pin with
 no files exits non-zero with the file unchanged, a yanked pin printed, a late file flagged <!-- audit-added: strongly-recommended -->
And a test asserts both committed files pass that check and name the engine's package at its tested version
And the pin set is unchanged: the `name==version` pairs before and after hashing are identical (a test or a
 recorded diff of the stripped lines)
```

## AC-3: A lab path is a directory this user owns and nobody else can write (T-12)
```gherkin
Given one function in engines.py, `check_lab_dir(path) -> None`, that raises `ValueError` naming the path and the
 reason unless the path is absolute, is a directory (following symlinks), is owned by `os.geteuid()`, and has
 neither group- nor other-write
When `runtimes._engine_env` is about to prefix a lab directory to PATH
Then it calls `check_lab_dir` after `expanduser`, and a failure is a `RuntimeStartError` carrying that message
 (the existing "nothing at" refusal keeps its wording)
When `record_lab_path` is called
Then it calls `check_lab_dir(bin_dir)` before reading or writing anything
And `record_lab_path` writes through `ohyesmlx.atomic_write_text(path, text)`, a new function in `__init__.py`:
 `tempfile.mkstemp` in the target's directory, write, flush, fsync, `os.replace`, temp removed on any failure.
 It is the one definition for this plan's writers; the other copies are listed in the SUMMARY (SCOPE LIMITS)
And this host's real lab directories still pass (`check_lab_dir` run read-only against both, output in the
 SUMMARY), so no harness run changes
And `detect_all` is unchanged: detection reports, starting refuses (its docstring already says so)
```

## AC-4: evict runs under the download lock (T-06)
```gherkin
Given `fetch.evict` gains `lock_dir=DEFAULT_LOCK_DIR`
When it is called after its consent and name checks
Then it takes `download.lock` with `_acquire_lock` before reading the ledger, refuses `busy` ("a download or
 eviction is running; nothing was removed") when it cannot, and releases it in a `finally`
And `_ledger_save` writes through `ohyesmlx.atomic_write_text`
And a test holding the lock (a live pid in the lock file) gets `busy`, the ledger and every listed file untouched
And no test reaches the real lock directory: every fetch test that calls `evict` passes a tmp `lock_dir`
 (a test or fixture fails if `DEFAULT_LOCK_DIR` is touched)
When quickbench's `evict` returns False (any refusal, `busy` included)
Then quickbench logs one event naming the repo and records it in the summary under `not_evicted`, instead of
 discarding the result; `docs/interfaces.md` lists `busy` for evict and the new summary key
```

## AC-6: A snapshot conflict is refused before any byte is requested (T-16)
```gherkin

```
