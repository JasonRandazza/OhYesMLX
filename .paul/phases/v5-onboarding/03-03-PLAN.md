<objective>
## Goal
`fetch.plan` and `fetch.download` put one catalog model into the Hugging Face hub cache layout (`blobs/`, `snapshots/<rev>/`, `refs/main`) with the standard library only: resumable by Range, sha256-verified, one at a time, and `fetch.evict` removes only what OYMLX itself downloaded.

## Purpose
Seam S5. Decisions (Jason, 2026-10-30): HF cache layout so all five engines see the model without extra setup; disk is scarce, so evict-before-fetch is a first-class, consented operation (D4). Research: `docs/research/2026-10-30-phase3-models.md` §2.6, §3 (stdlib is enough), §4.3 (disk guard).

## Output
`fetch.py` (module approved), tests with a fake transport, one manual smoke.
</objective>

<acceptance_criteria>

## AC-1: Consent gate, no network before it
Given `download(model, confirmed=False)`
Then nothing is opened and an error event `consent_required` is emitted and logged; `download` takes a catalog repo id, never a caller-supplied URL or path

## AC-2: HF cache layout
Given a successful download
Then each file lands as `blobs/<sha256>`, `snapshots/<revision>/<path>` is a relative symlink to it, `refs/main` holds the revision, under `models--<org>--<name>/` in the cache dir (default `~/.cache/huggingface/hub`, overridable through HF_HUB_CACHE and an injected path); huggingface_hub-style readers would accept it

## AC-3: Integrity
Given each file
Then its sha256 is verified against the catalog before the rename from `blobs/<sha256>.incomplete`; a mismatch deletes the partial file, raises/emit `integrity_failed` with the path, and nothing is symlinked into snapshots

## AC-4: Resume
Given a `.incomplete` of N bytes
Then the next attempt sends `Range: bytes=N-`, accepts only a 206 whose Content-Range starts at N (a 200 restarts from zero), and finishes with a verified file; an expired signed CDN URL (403/410) re-requests `resolve/<revision>/<path>` once for a fresh redirect

## AC-5: Hosts and URLs are constrained
Given redirects
Then only https hosts under huggingface.co or hf.co are followed; any other host is refused with `host_not_allowed`; the initial URL is built from `https://huggingface.co/<repo>/resolve/<revision>/<path>` only

## AC-6: Disk guard before the first byte
Given free disk (injected)
Then `download` refuses with `low_disk` unless free >= size_bytes*1.2 (one definition shared with recommend.py's constant, not a copy), before any request

## AC-7: One at a time, and a ledger
Given a running download
Then a second download is refused `busy`; every model the app downloads is recorded in `~/Library/Application Support/OhYesMLX/fetched.json` (repo, revision, time, bytes) and every event is appended to the install-style local log (no upload)

## AC-8: Evict touches only what we created <!-- audit-revised: must-have -->
Given `evict(repo, confirmed)`
Then it requires consent and removes EXACTLY the paths the ledger lists as created by a download (per-path `created_blobs`, `created_links`, `created_dirs`, not a blanket "the whole repo directory"); a repo absent from the ledger is refused; a foreign `models--...` directory, a foreign file inside a shared repo directory, and any blob still referenced by ANY snapshot symlink in the cache are never removed (reference-scan the whole cache before deleting a blob); every path is resolved inside the cache dir (no symlink escape); a missing or corrupt ledger makes evict refuse everything (fail closed)

## AC-9: Gated and missing repos
Given a 401 or 404
Then the event carries `X-Error-Code`-based reason ("gated" vs "not found"); neither retries

## AC-10: Retries and timeouts
Then each request has a timeout, transient errors (5xx, connection reset) retry with bounded backoff, and 429 honors Retry-After within a ceiling; all injectable (no real sleeps in tests)

## AC-11: Catalog-supplied names cannot escape <!-- audit-added: must-have -->
Given a repo id or file path from the catalog
Then the repo id must match `^[A-Za-z0-9._-]+/[A-Za-z0-9._-]+$`, every file path must be relative with no `..` segment, no leading `/`, no backslash and no NUL, sha256 must be 64 hex, revision 40 hex; each destination is resolved and must stay inside its snapshot directory; a violation raises before any network or write (tested with hostile literals, which also covers the later live Hub source)

## AC-12: Existing and partial downloads are preserved, not clobbered <!-- audit-added: must-have -->
Given the cache already holds some or all of the model (the user's own download of the same repo)
Then download verifies and reuses any blob whose sha256 matches, writes only missing blobs and links, records ONLY what it created in the ledger (so evict can never remove the user's copy), and a fully present model returns `already_present` with no network request

## AC-13: Bounded writes <!-- audit-added: must-have -->
Given a file whose catalog size is S
Then writing stops at S bytes; a response claiming or sending more (Content-Length, Content-Range or actual bytes) fails with `size_mismatch`, the partial is deleted, and nothing is linked

## AC-14: Anonymous only <!-- audit-added: must-have -->
Then no request carries an Authorization header and HF_TOKEN / HF_ENDPOINT are never read (a test asserts the headers of every request made through the fake transport); an HF_ENDPOINT mirror is out of scope

## AC-15: Atomic visibility <!-- audit-added: must-have -->
Then snapshot symlinks appear only after every file is verified, `refs/main` is written last, and a crash or cancel at any point leaves either nothing visible or a complete model; leftover `.incomplete` files are the only residue and are reused by resume or removed by evict

## AC-16: Disk guard counts what is missing <!-- audit-added: strongly recommended -->
Then AC-6's check uses missing bytes (not total) times 1.2, and is re-checked before each file

## AC-17: Cancel <!-- audit-added: strongly recommended -->
Then a cancel signal stops between chunks, emits `cancelled`, keeps `.incomplete` for resume, releases the lock, and logs it

## AC-18: Cross-process lock <!-- audit-added: strongly recommended -->
Then AC-7's lock is a lock file under Application Support (not only in memory) so two app instances cannot download the same repo at once; a stale lock from a dead pid is reclaimed
</acceptance_criteria>
